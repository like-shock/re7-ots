# 네이티브 OTS의 플레이어 캐릭터 지원

네이티브 OTS는 게임 진행 중 실제로 조작하게 되는 Ethan, Mia, Clancy, Chris, Joe,
Zoe를 구분한다. 캐릭터별로 3인칭을 막는 기본 설정은 없다. **각 캐릭터의 완전한 모습을
보려면 해당 캐릭터의 머리와 몸체가 들어 있는 외부 RT 모델 묶음이 설치되어 있어야 한다.**
DLL이 모델 파일을 생성하거나 다른 캐릭터로 교체하는 기능은 제공하지 않는다.

## 구현된 캐릭터 판별

아래 ID는 원본 RT 8.02의 캐릭터 판별 후크에서 읽는 값이다. 메뉴에서 캐릭터를 선택하는
기능이나 사용자가 변경해야 할 설정값이 아니다.

| 캐릭터 구분 | 원본 ID | 판별 내용 |
| --- | --- | --- |
| Ethan | `0`, `0xA` 등 기본 분기 | 다른 캐릭터와 일치하지 않으면 Ethan으로 처리한다. 메인 메뉴의 Joe 예외는 아래와 같다. |
| Chris | `1` | Not a Hero의 캐릭터 구분이다. |
| 현재 Mia | `2`, `3` 일부 | `3`은 플레이어 Z 좌표를 이용해 본편 Clancy와 구분한다. |
| 본편 Clancy | `4`, `3` 일부 | 본편 테이프의 캐릭터 구분이다. |
| 과거 Mia | `5`, `6` | 원본은 두 ID를 같은 구분으로 처리한다. |
| DLC Clancy | `8` | 본편 Clancy와 별도로 처리한다. |
| Zoe | `9` | Daughters의 캐릭터 구분이다. |
| Joe | 초기 상태 및 메인 메뉴 예외 | 원본은 End of Zoe에서 캐릭터 후크가 실행되지 않는 경우를 고려해 초기 상태를 Joe로 둔다. |

ID `3`은 원본의 비교 방식을 유지한다. 정상적인 좌표에서는 Z가 `35`보다 작으면 본편
Clancy, `35` 이상이면 현재 Mia다. 좌표를 읽지 못하거나 유효하지 않으면 이전 판별값을
보존하고 입력 준비 상태를 해제한다. 메인 메뉴 영역에서 명시적인 캐릭터 ID와 일치하지
않으면 Joe로 처리하며, 다른 영역에서는 Ethan 기본 분기를 따른다.

## 외부 모델 파일

사용자가 제공한 AfroJackX의 **Third Person Full Model Placeholders RT 1.0**에는 다음
8계열의 머리 리소스가 있다. 이 모델은 정적인 머리를 추가하는 묶음이며, 모델·재질·텍스처는
네이티브 OTS 배포 파일에 포함하지 않는다. **Ethan with Head RT만 설치하면 다른 캐릭터의
머리는 추가되지 않는다.** 전체 RT 묶음은 사용 중인 모델 관리 방법으로 별도 설치한다.
Fluffy 없는 설치와 Native 옵션은 [동봉 설명서](../diagnostics/native/README_KO.md)를 따른다.

| 계열 | 머리 리소스 경로의 끝부분 |
| --- | --- |
| Ethan | `pl0000/pl0002/pl0002.mesh` |
| Chris | `ch8/.../pl1000/pl1002/pl1002.mesh` |
| Joe | `ch9/.../pl9000/pl9002/pl9002.mesh` |
| Mia 2000 | `pl2000/pl2002/pl2002.mesh` |
| 현재 Mia 2100 | `pl2100/pl2102/pl2102.mesh`와 별도 머리카락 `pl2100/pl2100/pl2120.mesh` |
| Clancy 3000 | `pl3000/pl3002/pl3002.mesh` |
| Clancy 3100 | `pl3100/pl3102/pl3102.mesh` |
| Zoe | `pl3400/pl3402/pl3402.mesh` |

현재 Mia의 별도 머리카락 처리는 해당 AfroJackX 모델을 전제로 한다. 임의의 다른 커스텀
모델이나 다른 게임 빌드에 같은 주소와 구조가 적용된다고 보장하지 않는다. 위 표는 모델
파일 분석 결과이며, 각 ID에서 어떤 리소스가 실제로 생성되는지 전 구간을 장비에서
확인한 결과는 아니다.

## 1인칭으로 돌아가는 조건

원본의 머리 없는 모델 감지를 기본으로 사용한다. 판별용 값을 읽을 수 있고 값이 `1.0`이
아니면 머리 없는 모델로 간주해 1인칭을 유지한다. 본편·DLC Clancy에는 별도의 판별 위치를
사용한다. 이 선택적 값을 읽지 못한 사실만으로 3인칭을 차단하지는 않는다.

캐릭터별·구간별 강제 1인칭 설정은 기본적으로 꺼져 있다. 인벤토리, 이벤트, 잡힘, 특정
상호작용과 근접무기 등 원본의 전환 조건은 계속 적용된다. **Auto-Disable with Melee
Weapons**를 끄는 설정은 근접무기 조건만 바꾸며 이벤트와 인벤토리 조건은 유지한다.
원본처럼 Joe의 주먹 등 일부 무기는 근접무기 자동 전환이 켜져 있어도 3인칭 예외다.

## 검증 범위

자동 검사는 실제 `original_inputs.c`와 `original_state.c`를 실행하며, 게임 프로세스 읽기만
제어된 메모리로 대체한다. 모든 캐릭터 ID, 공유 ID `3`의 경계와 읽기 실패, Joe 초기 상태,
Clancy의 별도 판별 위치, 머리 없는 모델 감지와 읽기 실패, 캐릭터·구간별 기본 허용,
근접무기 설정과 이벤트 조건의 독립성을 검사한다.

이 검사는 **게임 화면에서의 머리·머리카락 표시, 애니메이션, 공격 명중, 모든 DLC의
이벤트 전환, Steam Deck/Proton 성능을 확인한 결과가 아니다.** 해당 장비 확인은 남아 있다.
같은 세이브에서 F6 전환, 인벤토리·이벤트 진입과 복귀, 각 캐릭터의 조준·공격을 확인하고,
문제가 있으면 캐릭터와 구간, 당시 동작, `native_*.jsonl` 로그를 함께 기록한다.

근거: `diagnostics/src/original_inputs.c`, `diagnostics/src/original_state.c`,
`diagnostics/tests/native_characters_host.c`, `diagnostics/lua/model/ethan.lua` 및
[기존 RT 모델 분석](RUNTIME_EXPANSION_KO.md). 모델·원본 CT 파일은 이 문서에 포함하지 않는다.
