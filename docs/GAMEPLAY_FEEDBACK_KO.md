# 실기 피드백과 v0.5.5-dev 복수 에단 머리 제어

에단 모델 표시와 좌우 어깨 전환은 사용자 확인 완료. 총기 조준, 자동 머리 숨김/표시는 아직 미확인이다.

| 보고 | 근거와 이번 처리 | 남은 확인 |
|---|---|---|
| 벽 옆에서 FP/OTS 반복 | 로그의 7회는 WAIT_NATIVE_INVALID. 당시 충돌 기능 OFF. nil/예외 읽기에 한해 즉시 1회 재시도 | 실제 파일 읽기 원인과 반복 전환 감소 여부 |
| 머리 제어 대기 | WAIT_MODEL_COMPONENTS949 표본. SystemArray의 C++ vector를 Lua table로 제한한 코드 결함 수정 | 실제 바인딩 성공과 FP에서 숨김 |
| A버튼 위치 어긋남 | 선택 가능한 PrerenderGUI 적용 경로, 이후 LockScene 소유권 확인 추가 | 실제 GUI 계산 시점과 옵션의 효과 |
| 가운데 조작 기준 어긋남 | 이동 전후 시선은 평행하며 원점이 달라 시차가 발생. 카메라 단계별 좌표 기록 | 실제 상호작용 목표/화면 투영과 선택 방향 보정 |
| 벽에서 손이 목 뒤에 표시 | PlayerHandTouch.HandIK 목표와 PlayerMotionController 상태를 읽는 진단 추가 | 어느 메시/애니메이션인지 확인 후 안전한 보정 |

두 로그는 같은 Lua 실행에 속하며 1,127개 표본, 잘못된 행/중복/충돌 0건이었다. 상태 파일 실패에서
약 67ms 후 새 표본이 나타났지만, 이전 로그는 nil·예외·잘못된 JSON 객체를 구분하지 못한다.
따라서 파일 교체 경쟁을 확정 원인으로 단정하지 않는다. 네이티브는 이미 임시 파일 + 원자적 교체를 사용한다.
재시도는 대기 없이 최대 2회 읽으며, 기존 마지막 표본으로 유효 시간을 연장하지 않는다.
조준·인벤토리·상호작용·로딩·세대·재전송·오래된 상태의 차단 조건은 유지한다.

모델 수정은 정확한 머리 경로/재질과 플레이어 하위 트리 검증을 유지한다. 배열 크기를 먼저 확인하고
0부터 인덱싱한다. 64개 초과, 잘못된 크기, nil 원소는 탐색 중단이며, 빈 배열은 정상적으로 건너뛴다.
게임 몸체, 팔, NPC와 알 수 없는 메시에는 쓰지 않는다.

새 실험 옵션 `Earlier HUD camera (experimental)`은 기본 OFF다. UpdateBehavior에서 원래 위치를
복원한 뒤 PrerenderGUI 전에 한 번 적용한다. LockScene에서 같은 카메라·같은 목표 위치인지 확인한다.
콜백 누락/순서 변경에는 대기, 외부 위치 변경에는 OFF로 전환하며 외부 좌표를 덮어쓰지 않는다.
실제 HUD 수정 완료나 상호작용 조준 보정 완료를 의미하지 않는다.

## 2026-10-16 추가 실기 결과

- 사용자가 `Earlier HUD camera (experimental)`를 ON으로 바꿔도 효과가 없다고 보고했다.
  이번 테스트에서 적용 시점 변경은 해결책이 되지 않았다. A버튼/화면 중심 문제는 미해결이며,
  이 옵션을 계속 켜거나 같은 비교를 반복하도록 안내하지 않는다.
- 벽 가까이에서 벽을 통과해 몸과 얼굴이 보이는 경우도 보고됐다. 카메라가 벽 뒤/내부로
  들어간 경우인지, 모델이 벽에 가려지지 않는 렌더링 현상인지 이 설명만으로 확정할 수 없다.
- 이번 실행의 충돌 설정과 로그는 아직 제공되지 않았다. 앞서 받은 v0.5.0 로그의 collision=false를
  이번 설정으로 간주하지 않는다. 반복 FP/OTS와 모델 바인딩이 v0.5.1에서 개선됐는지도 미확인이다.

소스상 Earlier HUD camera는 적용 시점만 바꾼다. 벽 거리 제한은 별도의
`Obstacle avoidance (experimental center ray)` 옵션이며 기본 OFF다. OFF이면 카메라 이동 전에
벽 검사를 하지 않는다. ON이어도 중심선만 검사하므로 카메라 가장자리·벽 내부·렌더링 가림까지
보장하지 않는다. 기존 설치본에서 Earlier HUD camera를 OFF, Obstacle avoidance를 ON으로 두면
충돌 경로를 확인할 수 있다. 이미 ON이었다면 동일 설정을 다시 반복할 필요가 없다.

다음 원인 판별에는 해당 실행의 play_0/play_1 로그 중 `camera.settings.collision`,
`camera.collision`, `phase_probe`, `model`을 사용한다. 충돌 미실행/조회 실패/접촉 누락과
모델 상태를 먼저 구분한다. CLEAR 기록만으로 벽이 없었다거나 깊이 테스트가 정상이라고
판정하지 않는다. 화면상 가림 여부는 짧은 영상이 추가로 도움이 될 수 있다.
이 기록 변경은 실행 코드 수정이나 벽 관통 해결을 의미하지 않으며 재설치는 필요 없다.

## 2026-10-16 후속 확인과 v0.5.2

사용자가 Obstacle avoidance는 완벽하지 않지만 효과가 있다고 확인했고, 이어 정지 상태에서도
FP/OTS 반복 전환이 여전히 발생한다고 보고했다. 충돌 완화의 부분 효과와 반복 전환 미해결을
분리해 기록한다. 최신 실행 로그는 아직 없으므로 이전 WAIT_NATIVE_INVALID와 같은 원인이라고
단정하거나, 새 보고를 전부 충돌 문제로 분류하지 않는다.

코드와 실제 Lua 어댑터를 사용한 재현에서 다음 결함을 확인했다.

- 기존 0.1 거리 하나로 FP 진입/이탈을 판단해, 고정된 플레이어·카메라에서 접촉 지점이
  0.219/0.221 사이로 흔들리면 clearance0.12를 뺀 결과가 경계를 반복 통과했다.
- 벽 접촉 사이에 한두 번 clear가 나오면 바로 뒤로 복귀했다. 일시적인 충돌 조회 오류 뒤에도
  오류 상태가 이전 거리 기록을 지워서 한 번의 성공만으로 복귀할 수 있었다.
- 진입 blend에 따라 충돌 검사 선분 길이도 바뀌었다. 새 코드는 최종 목표까지 검사한 후,
  확인된 거리 안에서 카메라 진입 blend와 최종 이동 속도 제한을 적용한다.

수정: FP 진입은 기존 안전 거리0.1 미만에서 즉시 수행한다. 복귀에는 여유 거리0.2 이상
(설정한 최종 거리가 더 짧으면 그 거리)이 0.4초 연속 확인되어야 한다. 관측 간격0.25초 초과나
시계 역행은 연속 확인 시간을 다시 시작한다. 조회 실패도 FP를 유지하며 안정화 후 복귀한다.
복귀 속도는 기존 초당1.5를 유지하고, 실제 첫 복귀 이동이0.1보다 작다고 다시 차단하지 않는다.
충돌 옵션을 켠 첫 진입에도 같은 속도 제한을 적용하므로 설정한 blend보다 진입이 길어질 수 있다.
모든 거리는 게임 좌표 단위다. 조준/OFF/네이티브 실패는 기존 즉시 복귀를 유지한다.

전환 로그에는 `collision_last`를 추가해 마지막 조회의 시각, 원인과 안정화 상태를 함께 남긴다.
이번 변경은 충돌의 중심선 범위나 물리 레이어를 늘리지 않으며, HUD/모델 깊이 렌더링은 수정하지 않는다.
충돌 경계에서 보류가 늘어 벽을 벗어난 뒤 복귀가 최소0.4초 늦어질 수 있다. 실기 반복 전환이
상태 파일 실패 등 다른 원인이라면 이 수정만으로는 없어지지 않을 수 있다.

개발 검증: 고정 위치의 경계 흔들림·짧은 clear·조회 실패 후 복귀·관측 공백·시계 역행·최종 목표
검사를 포함한 6개 회귀 사례에서 수정 전 실패와 수정 후 통과를 확인했다. 추가로60fps에서 작은
복귀 이동이 다시 FP로 잠기지 않는지와 조회 오류/네이티브 오류의 분리를 검사했다.
최종 독립 리뷰에서 긴 진입 blend(0.8초)와 복귀 제한을 함께 적용하면 최종 이동 속도가
초당1.875/2.25까지 커지는 Important 결함1건을 추가 재현했다. blend를 적용한 최종 거리에서
속도를 제한하도록 수정했다. 회귀 검사 실패 후 통과를 확인했고, clear 상태의 blend0이 차단으로
잠기지 않는 경우와 즉시 안쪽 이동도 검사했다. Critical/Minor 지적은 없었다.
`test.sh` 로컬 결과: C core30, observer12, Python/Lua164개 모두 통과(제공된 원본 CT 선택 검사 포함).
공개 CI는 원본 CT 없이 해당1개만 생략한다. 모의 접촉 입력으로 재현한 결함의 수정이며,
이번 사용자의 반복 전환 원인이 충돌인지까지 검증한 것은 아니다.

## 2026-10-16 얼굴 잔존 보고와 v0.5.3

사용자가 1인칭 전환 시 눈·코·입이 화면에 떠 있다고 보고했다. 사용 중인 정확한 빌드와 새
플레이 로그는 제공되지 않았으므로 원인을 확정하지 않는다. 제공된 Ethan RT 파일의 얼굴·눈·
머리카락은 동일한 pl0002 메시 안에 있다. 별도 얼굴 오브젝트 누락이라고 단정할 근거는 없다.

기존 코드는 GameObject의 DrawSelf만 변경·확인했다. EMV 고정 참조에서 실제 Draw를 별도로
확인하는 점과 Mesh의 `getMaterialsEnable(index)` / `setMaterialsEnable(index,bool)` 사용을
확인했다. DrawSelf 설정 성공만으로 얼굴 재질의 비활성까지 보장하지 않는 제어 범위를 보강한다.
원시 Draw 바이트나 관절 좌표는 변경하지 않는다.

- 로컬 플레이어 아래 정확한 경로·재질 집합·소유자·관절이 맞는 머리 메시의 재질만 제어한다.
- 각 재질 이름마다 독립 Visibility 제어기를 사용한다. 슬롯 순서가 바뀌면 이름으로 다시 찾고,
  쓰기 전 전체 트리 재검사·현재 값 비교·쓰기 후 읽기를 유지한다.
- 1인칭 복원 전에 모든 재질을 비활성화한다. 일부 실패 시 다른 재질의 숨김과 카메라 복원도 수행한다.
- 처음부터 비활성이던 재질은 3인칭에서도 켜지 않는다. 명시적 옵션 해제 시 소유한 원래 값만 복원한다.
- 세대 변경은 이전 소유값을 폐기한다. 잘못된 네이티브 상태에서는 이미 식별한 재질만 정리한다.
- 로그는 각 재질의 상태·원래 활성값, 마지막 DrawSelf/Draw 조회를 보존한다. Draw는 선택적 관측이다.

회귀 검사에서 기존 코드가 재질을 끄지 않던 경우의 실패와 수정 후 통과를 확인했다. 이는 모의
SDK 상태의 검증이며 눈·코·입 렌더링 자체를 재현한 것은 아니다. 부분 쓰기/예외, 무시된 쓰기,
외부 변경, 누락 API, 재질 순서 변경, 대상 교체, 원래 비활성값, 잘못된 native 상태, Mia의 두
부품과 실제 JSON 직렬화 시 로그 크기까지 검사한다. 재질별 쓰기 검증으로 SDK 호출이 늘어나며
실제 성능 영향·Draw와 렌더링의 관계·사용자가 본 얼굴 잔존의 해결 여부는 실기 미확인이다.
`test.sh` 로컬 결과: C core30, observer12, Python/Lua176개 통과(원본 CT 선택 검사 포함).

최종 독립 리뷰에서 소수 좌표와 Mia의 재질 정보를 한 sample에 넣으면 4,096바이트 한도를
넘어 자동 로그가 멈추는 Important 지적1건을 재현했다. 재질 상세를 분리하는 과정에서 Camera
관절·손 좌표까지 채운 phase_probe도 함께 있을 때 같은 한도 문제가 생김을 확인했다. 재질·
phase_probe를 별도 `scene_detail` 레코드로 옮기고 공통 session/run/lua_clock_s로 대응시켰다.
기존 sample의 모델 요약과 4,096바이트 한도는 유지한다. 소수 좌표·실제 JSON 인코더·채워진
단계/손 관측에서 실패 후 통과를 확인했다. 기존 요약 도구는 scene_detail을 건너뛰며 sample/
transition 집계는 유지한다. Critical/다른 Important 지적은 없었다.

## 2026-10-16 v0.5.3 실기 로그와 v0.5.4 진단

새로 전달된 두 파일은 모두 v0.5.3-dev의 동일 실행 로그다. 총 1,059개 sample에서
`WAIT_MODEL_AMBIGUOUS` 829개, `MATERIAL_pl0050_face:WAIT_MODEL` 89개,
`WAIT_MODEL_NATIVE` 140개, `DISABLED` 1개를 확인했다. 정상 숨김·표시 상태와 재질의
원래 활성값을 확보한 기록은 없다. 전체 모델 옵션을 꺼도 Ethan 부품 바인딩이 중복 판정에
막혔으며, 일부 시점에는 `WAIT_MODEL_COMPONENTS`도 기록됐다. 따라서 이번 실행에서는
재질 숨김 효과를 평가할 단계에 도달하지 않았다.

기존 중복 상태 하나에는 서로 다른 머리 오브젝트, 한 오브젝트의 복수 메시, 배열에 반복된
동일 메시 참조가 포함된다. 현재 로그만으로 어느 경우인지 확정할 수 없다. 이 조건을 해제하면
공유 오브젝트의 몸체까지 숨길 수 있으므로, v0.5.4에서는 선택·쓰기 보호 조건을 유지한다.
모호한 후보를 임의로 선택하거나 새로운 숨김 API를 적용하지 않는다.

- 자동 model_binding 레코드에 중복 종류, 오브젝트·메시의 스칼라 식별값, 메시 수와 고유 메시 수를 추가한다.
  배열 표본은 최대 4개이며 잘린 여부를 표시한다. 오브젝트 중복은 처음 발견한 두 후보만 기록한다.
- 배열 접근 실패도 세부 유형으로 남긴다. 정상 복구·세대 변경 시 이전 진단은 제거한다.
- 전체 모델/단일 Ethan 모드 모두 상세를 기록한다. 식별 실패 중 상위 `MATCHED_ETHAN_RT`가
  표시되던 문제를 수정한다. 새 설정 없이 기존 자동 로그 두 파일에서 확인한다.
- 메시·SDK 객체나 임의 경로 문자열은 진단에 보관하지 않는다. 최대 배열과 긴 식별값, 소수 좌표,
  손·카메라 단계 관측을 채워 실제 JSON 직렬화 후 4,096바이트 로그 한도 내 기록을 검사한다.

이는 원인 구분을 위한 진단 빌드다. 얼굴 잔존은 미해결이며, 실제 후보 구조는 다음 실기 로그가
필요하다. 원본 사용자 로그·모델 파일은 저장소나 배포본에 포함하지 않는다.
`test.sh` 로컬 결과: C core30, observer12, Python/Lua182개 통과(원본 CT 선택 검사 포함).
새 진단 회귀 검사는 구현 전 실패와 구현 후 통과를 확인했다. 게임 렌더링 검증은 포함하지 않는다.

최종 독립 리뷰의 Important 지적 1건: 정상 식별된 Mia 두 부품에 이후 중복 참조가 생기면
그룹·부품 진단과 재질·단계 관측을 합친 scene_detail이 4,174바이트가 되어 로그를 중단했다.
해당 상황을 회귀 검사로 추가해 실패를 재현하고, 모델 식별 상세를 `model_binding` 레코드로
분리했다. 모든 상세·재질·단계 관측을 유지하면서 한도 내 기록과 로그 지속을 확인했다.
다른 Critical/Important/Minor 지적은 없었다. 기존 요약 도구는 새 상세 레코드를 건너뛴다.

## 2026-10-16 v0.5.4 실기 로그와 v0.5.5 수정

새 두 파일은 v0.5.4-dev의 동일 실행·세대 기록이다. sample 866개 중 864개는
`WAIT_MODEL_AMBIGUOUS`, 2개는 `WAIT_MODEL_NATIVE`였다. model_binding 865개 모두
`MULTIPLE_HEAD_OBJECTS`이며 동일한 두 Ethan 프로필의 서로 다른 GameObject·Mesh를 가리켰다.
단일 오브젝트의 복수 메시나 배열의 중복 참조가 아니라, 개별 검증을 통과한 별도 머리 후보다.
진단은 처음 두 후보에서 멈췄으므로 전체 후보 수의 상한은 이 로그에서 알 수 없다.
보존된 sample의 카메라는 모두 OFF였다. 이번 로그는 모델 식별 중단 원인을 입증하며
카메라 충돌·전환 안정성의 새 검증 자료로 사용하지 않는다.

기존 단일 머리 가정을 수정한다. 복수 제어는 실기 증거가 있는 Ethan 계열에만 적용하며,
최대 4개까지 제한된 로컬 플레이어 트리를 완전히 검사한 뒤 각 인스턴스에 별도 제어기를 둔다.
각 객체의 경로·재질 집합·관절·소유 관계, 단일 메시 조건은 유지한다. 다른 객체 간 같은 메시
컴포넌트 공유, 공유 몸체 오브젝트, 다른 계열 중복·혼합, 초과 개수는 쓰기 전에 거부한다.

- 탐색 순서와 독립적인 식별값으로 대상을 고정한다. 모든 쓰기는 전체 트리 재검사와 값 비교를 유지한다.
- 각 인스턴스의 DrawSelf·재질 원래 값을 독립 보관한다. 1인칭에서는 모두 숨기고, 충분한 카메라
  이격 뒤 3인칭에서는 원래 값을 복원한다. 원래 숨겨진 복제 객체를 임의로 활성화하지 않는다.
- 집합 변경은 새 표시를 중단하고 알려진 대상 숨김을 시도한다. 새 세대에서는 현재 집합을 다시 확보한다.
  객체 교체나 외부 변경에 이전 원래 값을 덮어쓰지 않는다. 모델 실패가 카메라 복원을 막지 않는다.
- 전체 묶음과 Ethan 전용 모드 모두 적용한다. Mia 등 기존 단일 프로필/복수 부품 동작은 유지한다.
- UI에 인스턴스 수를 표시한다. `model_part`에 객체별 재질·Draw·대상 정보를 분리해 저장한다.
  `sample`과 `scene_detail`은 요약, `model_binding`은 실패 상세를 유지한다. 새 레코드도 같은
  session/run/lua_clock_s로 대응하며 기존 요약 도구의 전환 집계는 바뀌지 않는다.

새 회귀 검사는 수정 전 복수 후보 거부를 재현했다. 개별 원래 값, 순서 변경, 교체·추가·세대 변경,
각 머리의 카메라 이격, 공유 메시/몸체와 한도 초과 거부, 부분 실패 시 카메라 복원, 4개 인스턴스의
정상/실패 로그와 소수 좌표·손·단계 관측을 검증한다. 기존 진단 검사는 허용된 Ethan 복수 후보
대신 여전히 금지된 공유 오브젝트를 사용해 실패 표시를 확인하며, 재질 기록 검사는 model_part를 읽는다.

실제 얼굴 잔존·성능·목 연결·그림자와 복제 객체별 렌더링 역할은 아직 실기 미확인이다.
사용자 원본 로그와 모델 파일은 저장소나 설치본에 넣지 않는다.

## 검증

Lua SDK 경계 검사에 실제 SystemArray의 인덱스 API를 반영했다. 파일 읽기 일회/연속 실패,
재시도 후 조준·세대 변경·재전송, 배열 한도/중복/교체, GUI 전후 단계·중복/누락/재정렬,
다른 카메라·외부 위치 변경, 진단 오류 격리를 검사한다. 원본 CT를 사용하는 선택 검사도 로컬에서 실행한다.
실제 화면과 손 애니메이션은 위 표의 미확인 항목으로 남긴다. 사용자 원본 로그와 모델 파일은 배포하지 않는다.
