# 머리·모델 표시: 다음 개발 방향

2026-10-13. 이 문서는 개발 방향이다. 후속 구현으로 패키지 검사 도구와 표시 제어 모듈을 추가했으며,
실제 모델/REFramework 연결은 아직 없다. [현재 진행 내용](MODEL_SUPPORT_PROGRESS_KO.md)을 함께 참조한다.

## 목표와 확인 상태

목표는 기존 탐색 카메라에서 Ethan의 머리와 몸체를 볼 수 있게 하고, 1인칭 복귀 때 얼굴 안쪽이 화면을 가리지 않도록 제어하는 것이다. 사용자는 현재 Steam Deck을 사용할 수 없으므로, 자료 분석과 자동 검증을 먼저 진행하고 통합본이 준비된 뒤 플레이 중 확인한다.

- 사용자 확인: 몸체는 보임, 얼굴/머리는 없음.
- 사용자 보고: 걷기·계단에서 간헐적인 1인칭 복귀. 기둥 가림과의 연관성은 추정이며 원인이 확인되지 않음.
- 조준: 총이 없어 아직 미확인.
- 현재 구현: 카메라 위치만 변경하며 머리/몸체 렌더 상태는 수정하지 않음.

## 확인한 근거

원본 OTS 제작자의 [설치 안내](https://www.nexusmods.com/residentevil7/mods/12)는 RT 빌드에 AfroJackX의 [Third Person Full Model Placeholders](https://www.nexusmods.com/residentevil7/mods/86)를 권장한다. 구형 DX11용 Ethan with Head와 구분해야 한다. 원본 CT와 함께 제공된 크레딧도 별도 머리 모델 제작자의 기여를 명시한다.

[모델 파일 목록](https://www.nexusmods.com/residentevil7/mods/86?tab=files)에는 RT 본편용(Ethan, Clancy, Mia), Ethan/Mia만 포함한 본편용, DLC 포함 묶음이 따로 있다. 첫 구현 대상은 본편 Ethan으로 좁힌다. 이 모델의 파일 내용과 REFramework에서 실제 생성되는 객체 구조는 아직 열람·검증하지 않았다.

제공된 RT 8.02 CT에서 `HEAD_Y_WRITE`는 머리 생성 코드가 아니다. 1인칭 전환 상태를 계산하고, 식별한 머리·목·헬멧 등의 Y 좌표를 이동해 숨기는 코드가 섞여 있다. `PLAYER_TRANS_READ`와 `TRANS_GUN_WRITE`는 별도의 투명화/컬링 처리다. 이 패치들을 한 번에 적용하는 것은 카메라만 이동하는 현재 구조보다 범위가 크다.

따라서 머리가 없는 현상을 단순한 표시 플래그 버그로 단정할 수 없다. 설치된 모델 자산을 먼저 확인해야 한다. 모델 파일을 이번 Git 저장소에 재배포하지 않고 원본 배포처를 의존성으로 안내한다.

## 권장 접근

1. **RT 모델 연동 확인:** 선택할 모델 묶음의 리소스 경로, 메시 구성, 머리와 몸체의 분리 가능성을 확인한다. 모델 파일만으로 확인할 수 있는 항목부터 정리한다.
2. **표시 상태 제어 설계:** 카메라가 실제 3인칭 위치에 있을 때만 머리를 표시하고, 1인칭 복귀 전 머리를 숨기는 순서를 정의한다. 조준·인벤토리·자동 중단·F6 OFF·스크립트 재설정이 같은 규칙을 사용해야 한다.
3. **대상 식별과 복원:** 로딩·캐릭터 교체마다 대상을 다시 찾고, 자신이 변경한 값만 복원한다. 머리나 호환 API를 확인하지 못하면 잘못된 객체를 변경하지 않는다. 이름에 `head`가 있다는 이유만으로 다른 캐릭터까지 숨기지 않는다.
4. **통합 구현:** 모델 대상과 API가 확인된 후 카메라/모델 전환을 함께 연결한다. 머리를 표시할 수 없거나 숨김이 실패했을 때의 전환 방식도 명시적으로 처리한다.

머리를 항상 표시하는 자산 설치만으로 끝내는 방식은 1인칭에서 얼굴 내부가 보일 수 있다. 원본 CT의 좌표 후크 전체를 먼저 이식하는 방식은 캐릭터별 오프셋과 다른 패치 의존성이 크다. 확인된 모델과 대상별 표시 제어를 결합하는 접근을 우선한다. REFramework의 실제 객체와 메서드가 확인되기 전에는 API 이름을 추측해 런타임 코드를 추가하지 않는다.

## 실기 없이 진행 가능한 범위

- 모델 패키지의 리소스·메시 구성 분석(파일 확보 후).
- 3인칭 진입, 1인칭 복귀, 로딩/재획득의 순서와 상태 규칙 설계.
- 대상 없음, 다른 모델, 교체, setter 실패, 복구 실패를 포함한 제어 로직 자동 검사.
- 빌드, 패키징, 설치 문서와 원본 출처 관리.

실제 객체 구조, 모델 외형·목 연결·그림자와 렌더링 순서는 이후 한 번의 통합 플레이에서 확인할 부분이다. 자동 검사 통과를 모델 표시 성공으로 보고하지 않는다. 지금 추가 Steam Deck 실행이나 조준 시험을 요구하지 않는다.

## 카메라 복귀 문제와의 관계

이번 기능이 계단/걷기 중 1인칭 복귀 원인을 해결한다고 가정하지 않는다. 기존 자동 로그가 확보되면 상태값·거리·갱신 조건을 대조한다. 원인 확인 없이 카메라 중단 조건이나 대기 시간을 느슨하게 바꾸지 않는다.
