# 머리·모델 지원 진행 상황

2026-10-13. `work`에 **Explore Lua v0.4.0-dev의 Ethan RT 머리 제어**를 연결했다.
첨부 모델의 몸체/머리 분리 구조와 가중치를 분석하고, 대상 식별 및 카메라 전환 자동 검사를
추가했다. 게임에서 머리가 보이는지 확인한 단계는 아니다. 네이티브 DLL과 상태 프로토콜은
v0.3.0을 유지하며, 기존 카메라 중단 조건도 유지한다.

## 구현

- `model/ethan.lua`: 로컬 플레이어의 자식에서 정확한 메시 경로·재질·Head 관절을 확인한다.
  몸체, 다른 캐릭터, 여러 후보, 잘못된 부모 관계에는 쓰지 않는다.
- `model/visibility.lua`: 표시값 비교 후 쓰기, 읽기 확인, 소유한 변경의 복원을 담당한다.
- `model/session.lua`: 네이티브 세대별 수명 관리와 카메라/머리 전환 순서를 연결한다.
  모델 오류가 카메라 복원을 막지 않도록 처리한다.
- Explore 번들/UI: 기본 OFF인 `Ethan RT head model (experimental)` 옵션과 모델 로그를 추가했다.
  모델 설치 여부에 대한 선택만 저장하며, 카메라는 재실행마다 OFF다.

카메라 이동을 읽기로 확인하고 Head 위치와 0.60 m 이상 떨어졌을 때만 머리를 표시한다.
0.60 m는 보수적으로 선택한 개발 기준이며 실제 모델 크기·클리핑을 측정한 값은 아니다.
카메라 복원 전에는 머리를 숨긴다. F6 OFF, 조준, 인벤토리, 상호작용, 메뉴, 오래된 상태값,
스크립트 리셋도 이 경로를 따른다. 리셋은 머리를 숨겨 둔다.

머리 옵션을 명시적으로 끄면 아직 소유한 DrawSelf 값을 최초 상태로 복원한다. 원래 표시된
모델이면 다시 표시될 수 있다. 이것은 모델 파일 제거가 아니며, 원래 1인칭 외형으로 돌아가려면
게임을 종료하고 별도 설치한 모델도 해제해야 한다.

게임이나 다른 모드가 값을 바꾸면 덮어쓰지 않고 오류를 유지한다. 실패 후 새 플레이어 세대가
확인되거나 옵션 해제·재활성화로 새 수명주기를 시작하기 전까지 표시를 재시도하지 않는다.
숨김이 실패해도 카메라는 복원하므로 얼굴이 화면을 가릴 가능성은 남는다.

## 자산 및 설치

사용자가 제공한 **Ethan with Head RT** 파일 분석은 완료했다. 다시 파일을 받을 필요가 없다.
[분석 결과와 API 근거](ETHAN_RT_MODEL_ANALYSIS_KO.md),
[설치·사용 안내](../diagnostics/EXPLORE_README_KO.md)를 참조한다.
게임·외부 모델·REFramework 바이너리는 저장소나 Explore 설치 ZIP에 포함하지 않는다.

기존 `tools/inspect_model_package.py`는 ZIP/압축 해제 폴더의 경로·크기·해시 목록을 만드는
읽기 전용 도구다. RAR/7z는 먼저 별도 폴더로 압축을 해제한다. 이 도구 자체는 모델 구조나
RT 호환성을 판정하지 않으며 보고서의 `compatibility`는 `UNVERIFIED`다.
패키지 검사기의 기존 경미한 후속 항목(LZMA 손상 파일의 오류 메시지, 암시적 부모 경로의
대소문자 충돌 판정)은 이번 런타임 연결 변경에 포함하지 않았다.

## 검증과 다음 확인

실제 Lua 5.4에서 SDK 경계만 모의 처리해 모델 선택, 중복/교체, 쓰기 실패, 세대 변경,
카메라와 머리의 전환 순서를 검사한다. 전체 C/DLL/Lua 검사는 `bash diagnostics/test.sh`로 실행한다.
결과와 독립 검토 기록은 [구현 계획/기록](superpowers/plans/2026-10-13-ethan-head-binding.md)에 남긴다.

현재 Steam Deck 실행을 추가로 요구하지 않는다. 사용할 수 있을 때 통합본으로 실제 객체 구조,
외형·목 연결·그림자, 컬링과 성능을 확인하면 된다. 걷기·계단에서 간헐적으로 1인칭으로
돌아오는 현상은 원인이 확인되지 않았으며, 이번 머리 연결로 해결했다고 보지 않는다.
