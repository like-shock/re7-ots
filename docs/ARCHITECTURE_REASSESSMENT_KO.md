# 반복되는 실기 문제에 대한 구조 재검토

검토일: 2026-10-17. 코드 기준: `aac792c` / Explore v0.5.9-dev / native v0.3.1.
새 사용자 결과: 3인칭은 빨라졌지만 여전히 1인칭보다 느리고, 나머지 수정사항은 개선 없음.
이 보고를 반영해 반복 전환·좌표·벽·손 문제를 해결 상태로 취급하지 않는다.
이번 변경은 조사 도구와 기록이며 게임 실행 코드는 바꾸지 않는다.

## 판단

**RE7의 3인칭 자체가 불가능하다는 근거는 없다. 그러나 현재 Explore 구조에 국소 보정을
계속 추가하는 방식은 권장하지 않는다.** 현재 구현은 원본 CT의 완전한 이식이 아니라,
1인칭 게임 처리 뒤 카메라 위치를 바꾸고 표시를 복구하는 탐색용 시제품이다.
원본과 동등한 좌표·충돌·모션 제어가 이미 구현됐다고 볼 수 없다.

다음 단계는 제한된 구조 검증이다. 상태 전달과 머리 제어 비용을 프레임 제어에서 분리하고,
최종 카메라와 게임의 상호작용 판정이 같은 기준을 사용하도록 통합할 수 있는지 먼저 입증한다.
이 검증에 실패하면 현재 구현의 기능 확장은 중단하고, 대상 게임 버전에 맞춘 네이티브 이식 또는
탐색 전용으로 범위를 줄이는 결정을 해야 한다. 네이티브로 바꾸기만 하면 해결된다는 뜻은 아니다.

## 새로 확인한 구조적 문제

### 1. 실제 시점 전환이 없어도 머리를 매 프레임 숨겼다가 다시 표시한다

`adapter.lua`의 `on_update()`는 매 프레임 `restore_owned()`를 호출한다.
`on_camera()`도 이를 호출한다. `restore_owned()`는 카메라 복원 여부를 확인하기 **전에**
머리의 `before_restore()`를 실행하며, 성공한 카메라 적용 뒤 `after_apply()`가 표시를 되돌린다.
`session.lua`는 각 재질과 DrawSelf를 별도로 제어하고, `ethan.lua`는 쓰기마다 대상을 재확인한다.

이전 최적화는 이 반복 작업 내부의 조회를 줄였지만 반복 자체를 없애지 않았다.
현재 코드와 기존 SDK 모의 트리를 사용해 100프레임씩 다시 계수했다.
조건: 검증된 머리 2개, 별도 노드 60개, 각 머리의 재질 5개가 원래 활성 상태.

| 프레임당 작업 | 3인칭 유지 | 1인칭 유지 |
|---|---:|---:|
| 계수된 SDK 경계 호출 | 6,631 | 398 |
| DrawSelf 쓰기 | 4 | 0 |
| 재질 활성값 쓰기 | 20 | 0 |
| 전체 트리 검사 | 3 | 0 |

실기 FPS나 호출당 비용을 측정한 수치가 아니다. 모델이 다시 숨겨지거나 표시되는 모든 순간이
화면에 그려진다는 증거도 아니다. 다만 3인칭에서만 추가되는 큰 작업량은 실제 코드 경로다.
개선 방향은 실제 표시 상태 변화와 내부 카메라 복원을 분리하고, 렌더링 경계·엔진의 재설정 여부를
확인한 뒤 필요한 변경만 수행하는 것이다. 엔진이 매 프레임 값을 덮어쓰는지 확인하지 않고
단순히 모든 재검증·숨김을 제거해서는 안 된다.

### 2. 중심선 검사는 한 프레임에 물리 질의 31회를 수행한다

`physics.lua`의 `cast()`는 레이어 0~32 중 7·18을 제외한 모든 레이어를 순회한다.
벽이 없는 모의 경로 100회에서 프레임당 cast 31회, query/result 객체 생성 2회를 확인했다.
접촉점이 있으면 각 점의 플레이어 소유 관계도 순회한다.

이는 충돌 옵션이 ON인 적용 프레임의 비용이며 OFF인 실행에는 해당하지 않는다.
여러 레이어를 조회해도 선의 두께는 늘어나지 않으므로 카메라 가장자리 관통은 남을 수 있다.
확인된 월드 충돌 마스크와 카메라 폭을 고려한 질의 또는 원본의 거리 계산 경로가 필요하다.
현재 마스크의 의미가 확인되기 전에 임의로 한 레이어로 줄이는 것은 해결책이 아니다.

### 3. 프레임 지연과 자동 복귀가 반복되는 구조를 파일 실패 없이 재현했다

현재 `core.lua`는 소비한 두 표본의 tick 차이 또는 Lua 폴링 간격이 350ms를 넘으면
준비 상태를 해제한다. 정상 상태가 다시 0.5초 이상 이어져야 3인칭이 가능해진다.
`adapter.lua`는 `on_frame()`에서 파일을 읽고, 별도 엔진 콜백에서 이 준비 상태를 사용한다.

이번 모의 입력은 생산자가 50ms마다 계속 정상 상태를 생성하고 파일 실패 횟수도 0인 조건이다.
소비자만 400ms 동안 표본을 읽지 못하게 하면 seq는 8 증가하고 `WARMUP / NATIVE_GAP`으로
내려간다. 이후 50ms 간격의 가벼운 프레임 12개를 주면 READY로 복귀한다.
이 입력을 5회 반복하자 5회 모두 같은 왕복이 발생했다. 벽·이동·조준 신호는 필요하지 않았다.

중요한 해석: **현재 `NATIVE_GAP`은 생산자의 저장 실패를 증명하지 않는다.** 소비자가 중간
표본을 놓쳐도 같은 tick 차이가 발생한다. 실제로는 생산자 공백과 소비자 지연을 분리해야 한다.
모델/충돌 처리 비용 → 프레임 지연 → 1인칭 복귀 → 처리량 감소 → 3인칭 복귀라는 연결은
가능한 가설이다. **400ms는 주입한 지연이며 사용자의 실제 프레임 시간이 아니다.**
보통의 30/60 FPS 저하만으로 350ms 기준을 넘는다는 주장도 아니다.

v0.5.9의 250ms 저장 실패 대기 제거는 그 경로의 증폭만 고쳤다. 이 소비자 지연 경로와
다른 입력 무효·세대 변화·충돌 경로는 고치지 않았다. 최신 실행의 로그 없이 어느 경로가
사용자의 현재 반복 전환을 일으키는지는 확정할 수 없다.

추가로 `journal.lua`는 각 레코드마다 동기 `write()`와 `flush()`를 수행한다.
2개 머리가 있으면 주기적인 모델 상세와 표본 등 여러 레코드를 같은 `on_frame()`에서 쓴다.
오류가 카메라로 전파되지 않게 처리해도 I/O 소요 시간까지 분리되는 것은 아니다.
이는 추가 비용 후보이며 실제 저장 장치 지연을 측정한 결과는 아니다.

### 4. 화면 카메라·버튼·게임 판정의 기준이 통합되어 있지 않다

기본 경로는 UpdateBehavior 전에 원래 카메라를 복원하고 LockScene 전에 OTS 위치를 적용한다.
버튼 보정은 GUI draw 콜백에서 제한된 UI 컨트롤을 바꾸며 게임의 대상 선택 방향은 바꾸지 않는다.
원본 CT의 `FIRING_COOR_WRITES`는 별도 사격 원점에 카메라 좌표를 복사하며,
`TP_INTERACTABLE_COORDS`는 특정 조사/확인 프롬프트 경로를 별도로 다룬다.
일반 물체 선택이 그 사격 원점과 동일한 필드를 사용한다고 증명된 것은 아니다.

현재 prompt 보정은 부모 변환이 없고 원래 UI 위치가 예상 투영과 일치해야 적용한다.
실제 UI 배치가 다르면 정상적으로 보정을 거부하므로, 함수가 등록됐거나 모의 투영 테스트가
통과했다는 사실만으로 실제 버튼에 적용됐다고 볼 수 없다. 최신 실기의 어느 조건에서 멈췄는지는 미확인이다.
손 접촉 모션도 여전히 원래 게임이 제어하며, 현재 코드는 해당 값을 관찰할 뿐 보정하지 않는다.

## 왜 기존 검사로 충분하지 않았나

- 224개 테스트는 복원·오류 처리·경계값·가정한 SDK 구조를 검증한다. 실제 게임의 대상 선택,
  UI 부모 변환, 렌더링 순서, 물리 레이어 의미를 입증하지 않는다.
- 기본 어댑터 fixture는 시간을 직접 0.1초씩 진행시킨다. SDK 호출·파일 읽기·flush는
  실제 엔진 시간만큼 진행되지 않는다. 따라서 무거운 작업과 준비 상태의 상호작용이 빠져 있었다.
- 기존 성능 검사의 7,000회 미만 조건은 이전 구현보다 호출이 줄었는지를 보며,
  Steam Deck에서 허용 가능한 프레임 시간인지 판단하는 기준이 아니다.
- 지금까지 실제 결함을 고친 부분은 있지만, 그것을 최신 실기 증상의 원인과 연결하는 증거가 부족했다.
  추가 모의 검사 통과를 근거로 다시 해결 가능성을 과장해서는 안 된다.

## 대안과 실행 가능성

| 방향 | 판단 | 근거·남는 위험 |
|---|---|---|
| 현재 구조에서 임계값·지연·조회 캐시만 추가 조정 | 중단 권고 | 서로 다른 판정 기준과 프레임당 반복 쓰기가 유지된다. |
| REFramework 안에서 프레임 제어를 통합 | 우선 검증 | 파일 왕복 없는 상태 API, 비용이 큰 코드의 네이티브 실행은 공식 지원 경로다. 실제 게임 경계는 별도 확인해야 한다. |
| 원본 CT의 필요한 후크를 네이티브 플러그인으로 이식 | 조건부 가능 | 원본이 사용하는 제어 지점이 있다. 현재 빌드의 명령·객체·호출 맥락을 검증해야 하며 주소 복사만으로 끝나지 않는다. |
| RE7 3인칭 개발 자체를 포기 | 현재 근거로는 이르다 | 모델 표시와 시점 이동이 이미 작동한다. 단, 원본 존재가 현재 빌드/Deck의 성능·완전 호환 보장은 아니다. |

공식 REFramework 문서는 메서드/필드 정의 캐시와 무거운 작업의 native plugin 실행,
Lua에 API를 노출하는 방식을 제공한다. 고정 참조의 example_plugin에도 Lua state 등록과
애플리케이션 콜백 예제가 있다. 따라서 JSON 파일은 필수 통신 방식이 아니다.
다만 직접 전달만 도입해도 엔진 스레드가 멈춘 시간이나 잘못된 상태 판정이 자동 해결되지는 않는다.

`os.clock`도 확인했다. 일반 POSIX CPU 시간 의미만 적용해 원인이라고 단정할 수 없다.
Microsoft CRT는 elapsed wall time으로 문서화한다. 실제 사용 DLL/호환 계층과 독립 단조 시계의
차이는 다음 계측에서 확인할 사항이며, 이번 원인 판정에는 사용하지 않았다.

## 다음 검증 범위와 중단 기준

다음 단계는 광범위한 기능 추가가 아니라 **본편 에단·한 게임 빌드에 한정한 통합 시제품**이다.
실기 확인 전에는 이를 해결 버전으로 배포하지 않는다. 설정 조합을 사용자에게 계속 바꾸게 하기보다
한 실행에서 원인별 시간·상태·실제 보정 적용 결과를 자동 수집하도록 준비한다.

1. 상태 전달: 게임 제어 콜백에서 최신 상태를 직접 읽거나 같은 프로세스의 API로 전달한다.
   생산자·소비자 시간과 프레임 소요 시간을 구분하고, 로그 flush는 제어 경로 밖으로 옮긴다.
   오래된 상태를 그대로 유효하게 취급하거나 모든 자동 복귀를 끄지 않는다.
2. 모델: 내부 카메라 복원과 실제 1인칭 전환을 분리한다. 엔진이 덮어쓰는 값과 렌더링 경계를
   확인한 뒤 표시 변경을 최소화한다. 객체 수명·교체 검증은 유지하고 비싼 탐색은 매 재질 쓰기에서 분리한다.
3. 좌표: 선택 원점·시선·화면 투영과 실제 적용 시점을 측정한다. 본편의 해당 게임 함수/필드가
   확인되면 그 경계에서 통합한다. 프롬프트 위치만 맞추고 대상 선택이 어긋난 상태를 완료로 보지 않는다.
4. 충돌/손: 월드 충돌 범위와 손 접촉 모션의 실제 소유자를 확인한 후 작업한다.
   광범위한 물리 레이어 조회에 추가 ray만 늘리는 방식은 피한다.

계속 진행할 판단 기준은 (a) 동일 장면의 정지·보행 5분 동안 의도하지 않은 왕복 전환 0회,
(b) 동일 설정·장면에서 기능별 프레임 시간 증가량을 실제로 측정할 수 있음,
(c) 가까운/먼 상호작용 물체와 양쪽 어깨에서 화면 표시·대상 선택이 함께 일치함이다.
성능 1차 목표는 비교 가능한 동일 장면의 중앙 프레임 시간 증가 10% 이내로 제안한다.
이는 실측이나 보장 수치가 아니며 GPU/CPU 제한과 프레임 제한에 따라 해석해야 한다.
조준·인벤토리 등 의도된 1인칭 전환은 반복 오류 집계와 구분한다.

필요한 엔진 제어 지점을 확인할 수 없거나, 통합한 최소 시제품에서도 위 기준에 접근하지 못하면
현재 접근을 중단한다. 무기·다른 캐릭터·DLC를 확장하며 문제를 뒤로 미루지 않는다.
현재 환경에는 실행 가능한 RE7 런타임과 최신 게임 실행 로그가 없으므로,
이 실기 판정을 오프라인 검사만으로 완료할 수는 없다.

## 재현 및 근거

저장소 루트에서 실행:

```sh
python3 diagnostics/tools/probe_runtime_architecture.py
```

이 도구는 게임 파일·사용자 로그를 읽지 않고 현재 Lua와 기존 SDK fixture를 사용한다.
현재 버전의 동작을 관찰하는 조사 도구이며 향후 변경을 막는 회귀 검사로 등록하지 않는다.
실행 결과: 위 모델 호출 수, clear 경로 cast 31회, 소비자 지연에 따른 WARMUP/READY 왕복 5회를 확인했다.
