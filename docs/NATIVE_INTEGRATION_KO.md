# 원본 네이티브 통합 0.1.3

2026-10-17. `RE7_OTS_Native.dll`은 원본 RT 8.02의 제어 경로를 게임 훅에 연결한
실제 3인칭 플레이 시험용 빌드다. 별도 NativeProbe 로그를 먼저 받는 단계는 제거했다.
기존 13개 로그에는 원본 훅의 실시간 레지스터·실행 순서가 없지만, 원본 CT와 기존
78개 위치의 바이트 대조 결과로 구현을 진행할 수 있다. 새 통합본의 실제 화면과 성능은
그 빌드를 실행해야 확인할 수 있다.

설치·복구·시험 방법은 [동봉 설명서](../diagnostics/native/README_KO.md)를 따른다.
F6으로 3인칭 카메라를 켜고 끄며 F7으로 어깨를 바꾼다. 실행 직후 3인칭은 OFF다.
모델 파일은 기존 설치본을 사용한다. 0.1.3의 1인칭 머리 숨김은 별도 체크박스로 제어하며 기본 ON이다.

## 연결한 제어

| 경로 | 통합 내용 |
| --- | --- |
| 카메라 | 원본 카메라 주소 수집과 대상 비교, pitch, X/Y 처리 후 Z 배율 갱신, 원본 FP/TP 분기 |
| 시점 상태 | 지역·캐릭터·인벤토리·조준·사다리·이벤트·FOV·무기 가림, 원본 전환/복귀 순서 |
| 조준 | 원본 focus 증분과 총 가림 전환, 현재 카메라 전체 XYZ를 발사 원점에 적용 |
| 상호작용 | 원본의 문서·주 조사 물체·보조 물체·F-prompt 대상 비교 후 XYZ 보정 |
| 충돌 | 원본 DOF 거리·방향 입력, 수축/복귀·완충 구간, 일반/NAH/EOZ 명령 형식 |
| 모델 | 원본 투명도 읽기/쓰기 경로. 머리·재질·SDK 오브젝트 탐색 없음 |
| 손전등 그림자 (0.1.1) | 원본 손전등 주소와 일치하는 3인칭 그림자 쓰기에만 원본 해제값 적용 |
| 설정 UI (0.1.3) | 근접무기 자동 전환과 1인칭 머리 숨김의 독립 체크박스·자동 저장 |
| 1인칭 머리 (0.1.3) | 원본 네 가지 목/머리/헬멧 위치, 손전등 머리 그림자, 현재 Mia 머리카락 |
| 동작 진단 | 실제 훅별 호출/적용 수, 카메라 주소, 입력 유효성, 시점 전환·실패 수, 카메라/충돌 배율 |

Lua 경유와 렌더 카메라 사후 보정을 제거하고 원본이 사용한 쓰기 위치를 사용한다.
카메라 근접 거리나 FPS를 새로운 1인칭 전환 조건으로 삼지 않는다. 원본의 의도적인
1인칭 전환 조건은 유지하므로 모든 상황에서 3인칭을 고정하는 구현은 아니다.
2026-10-18 사용자는 테스트한 플레이에서 일반 상호작용 버튼 틀어짐이 해결됐다고 보고했다.

## 실행 조건과 실패 처리

- 지원 실행 파일 SHA-256은
  `d550260029b51a580e206b9a12a4eb7f4a1b4dd230bba5defcca81da40597321`이다.
  PE 정보·전체 파일 해시·42개 훅의 원본 바이트·실행 메모리 속성이 모두 맞아야 설치한다.
- 카메라 대상이 다르면 원래 명령을 실행한다. 필수 상태나 전체 좌표를 읽을 수 없으면
  보정을 적용하지 않는다. 순서대로 읽고 쓰는 원본 명령과 충돌할 수 있는 입력/출력
  메모리 겹침도 원래 명령으로 통과시킨다. 실패한 이벤트 입력은 원본이 제공한 주소로 재확인하며,
  선택적인 모델 마커 읽기 실패는 3인칭의 선행 조건이 아니다.
- C 호출 전 모든 일반 레지스터·플래그·운영체제가 활성화한 확장 CPU 상태를 저장한다.
  C 계산은 초기화한 x87/SSE 환경을 사용하고 호출 후 게임 상태를 복원한다.
  처리한 명령은 원래 메모리 쓰기뿐 아니라 EAX/ECX/XMM의 결과도 재현한다.
- 완료된 C 호출 프레임의 스택 추적은 원래 게임의 훅 위치·스택·비휘발성
  레지스터/XMM으로 복원하도록 별도 machine frame과 unwind 정보를 사용한다.
  연결된 DLL의 unwind 코드를 실행하는 모의 검사로 이를 확인했다. 첫 진입 PUSH와
  마지막 전송 JMP의 짧은 경계, 실제 Windows/CET 예외 전달은 이 검사 범위 밖이다.
  자동 예외 복구를 보장하는 기능으로 간주하지 않는다.
- 공유 상태는 직렬화하며 훅 안에서 파일 기록이나 SDK 호출을 하지 않는다.
  로그는 별도 작업 스레드가 약 250ms 간격으로 기록하며 8MB에 도달하면 기록만 멈춘다.
  `present_fps`는 그 구간의 실제 화면 출력 횟수로 계산하므로 F6 비활성 상태에서도
  비교할 수 있다. 원본 계산용 `fps`는 하한 보정이 있으므로 실측 FPS와 구분한다.
- 훅 DLL과 트램펄린은 프로세스 종료까지 유지한다. F6 OFF는 카메라·조준·상호작용을 원래 명령 실행으로
  돌린다. 1인칭 머리 숨김이 ON이면 그 경로만 남고, 두 기능이 모두 OFF면 모든 원래 명령을 실행한다. 게임 실행 중 설치 파일을 교체하지 않는다.

## 검증 범위와 남은 확인

원본 명령을 이용한 대조에는 스칼라 식 6,000건, 충돌 1,800건, 상태 정책 1,500건,
카메라 전환 3,000건이 포함된다. 별도 호스트 검사는 실제 어셈블리 브리지 48개를
실행해 레지스터·플래그·x87/SSE/AVX 보존과 처리/통과 경로를 확인한다. 통합 검사는
대상이 아닌 카메라의 무변경, 입력/쓰기 실패, XYZ/W 쓰기와 레지스터 결과,
일반/NAH/EOZ 형식, 모델 투명도, 조사 물체와 시점 정책 연결을 검사한다.
독립 리뷰에서 발견한 원본 입력 좌표와 보정된 표시 좌표의 혼용도 분리했다.
마지막 보스 구간의 원본 전환 조건을 실제 카메라 어댑터에 통과시키는 재현 검사가
이 구분을 확인한다. 단위 계산의 일치만으로 연결부까지 검증됐다고 간주하지 않는다.

이 오프라인 검사는 Steam Deck에서 원본과 같은 화면·조작감·FPS라는 증거는 아니다.
2026-10-18 실기 보고에서 손 문제·반복 전환·버튼 위치는 해결 확인됐고 시점 중심도
해결된 것으로 보인다고 했다. 캐릭터가 검게 보이는 문제가 새로 보고됐으며,
후속 비교에서는 RELit OFF 시 정상 색으로 돌아오는 것이 확인됐다.
3인칭 성능·총기 조준·남은 벽 관통 상황은 이번 보고로 판단할 수 없다.
현장 실행이 실패하면 같은 실행의 `native_*.jsonl`과 `reframework.log`로
훅 설치 실패인지, 상태 입력 실패인지, 실제 계산 적용 후의 화면 문제인지 구분한다.

원본 CT 전체 기능의 완성판은 아니다. 자유 카메라/잠금,
사용자 정의 FOV와 달리기 FOV 덮어쓰기, 수동 손전등·치트·프리셋 UI는 포함하지 않는다.
원본의 달리기 거리 변화와 프레임별 focus 증분은 연결했지만 FOV 자체는 게임 값을 사용한다.
원본 CT·게임 실행 파일·모델 자산은 배포하지 않는다.

빌드: `bash diagnostics/native_build.sh`. 전체 검사: `bash diagnostics/test.sh`.
비공개 원본 대조는 `RE7_CT_FILE`과 `RE7_ORIGINAL_NUMBERED_SOURCE` 경로를 지정한다.
패키지: `python3 diagnostics/tools/package_native.py dist`.
패키지는 깨끗한 Git 커밋, 실제 컴파일 소스 해시, 고정 MinHook 해시, DLL 해시를 검증한다.

## 2026-10-18 후속 실기 결과 — RELit 추가 조명

사용자는 검은 표시가 여전하지만, RELit의 카메라 추적 조명이 캐릭터 그림자를 만들고
RELit를 끄면 정상 색이 된다고 확인했다. 이번 보고의 설치 버전은 명시되지 않았다.
이는 시험한 환경에서 RELit 병용이 발생 조건임을 보여준다. 이후 사용자는
**`Enable Shadows`가 이미 OFF인 상태에서도 발생한다**고 명확히 했다.
따라서 단순히 그림자 옵션이 켜져 있다는 가설과 같은 옵션을 다시 끄라는 안내는 제외한다.
실제 렌더링 원인과 엔진의 다른 조명 경로까지 구분된 상태는 아니다.
이어 사용자는 **F8로 조명만 OFF해서 정상 색으로 돌아왔다**고 확인했다.
따라서 스크립트 전체 제거가 아니라 추가 조명 활성 상태에 따라 증상이 달라지는 비교다.

확인한 [공개 RELit 소스](https://github.com/originalnicodr/RELit/blob/11231ea44ffc92225e7fcf92fd7e9efb64b5f921/RELit.lua)
(`relitVersion = 1.2.1`)는 별도 SpotLight/PointLight를 생성하고 카메라에 부착한다.
조명별 `Edit → Shadow Settings → Enable Shadows`가 `set_ShadowEnable`에 연결되어 있다.
`handle_bool_value`는 매번 실제 getter 값을 읽고 값이 바뀔 때 setter를 호출한다.
공개 소스에는 이 값을 매 프레임 ON으로 강제하는 경로가 보이지 않는다. 사용자 설치 버전이나
엔진 내부 렌더링까지 이 사실만으로 보증하지 않는다.

`Lights`의 이름 옆 체크는 해당 조명 `set_Enabled`만 변경한다. 카메라 추적은 별도
`attachedToCam` 조건으로, 수동 노출은 `customTonemapping.autoExposure`가 false일 때
별도 프레임 콜백에서 처리한다. 이번 사용자 확인은 조명만 OFF한 비교로 분류한다.
조명만 OFF해서 개선돼도 광량 변화에 따른 게임의
자동 노출 반응까지 배제되는 것은 아니다. `Show RELit UI`는 창 표시만 조절한다.

공개 RELit의 카메라 추적은 primary camera GameObject의 Transform 위치·회전·WorldMatrix를
조명 Transform에 복사한다. Native는 원본 카메라 쓰기 훅에서 좌표를 보정한다.
두 경로의 코드가 존재한다는 사실만으로 같은 프레임에 같은 최종 좌표를 읽는다고
보장할 수 없으며, 반대로 불일치가 이번 원인이라고 단정할 수도 없다.
현재 자료에는 증상 시점의 실제 광원 위치·노출값·렌더링 결과가 없어 이 구분이 남아 있다.

`Save settings as default`는 현재 조명 속성을 기본값에 복사해
`reframework/data/RELit_config.json`에 저장한다. 그림자뿐 아니라 밝기·색상 등도 포함하며,
조명 생성이나 카메라 부착 상태의 자동 복원은 이 저장 경로에 포함되지 않는다.

Native 0.1.1의 `flashlight_shadow_write`는 원본 손전등 주소 비교를 통과한 대상만 처리한다.
RELit 추가 조명을 검색하거나 수정하지 않으므로 이 변경으로 이번 문제가 남는 것은 범위상
설명된다. 현재 네이티브 코드의 대상 비교를 확대하거나 모델 재질을 수정할 근거는 없다.
확인되지 않은 밝기·노출·재질 강제 보정은 추가하지 않는다.
이번 업데이트는 피드백·설명서만 변경하며 DLL은 유지한다.

## 이전 조사: 2026-10-18 캐릭터가 검게 보이는 현상 (0.1.0 기준)

사용자는 캐릭터가 완전한 검정은 아니지만 대부분 검게 보이고, 색이 반전된 듯하다고
설명했다. 당시 화면·새 로그가 없어 단순한 어두움, 그림자, 재질/노멀 이상을 구분할 수 없었다.
아래 원본 참조는 기존 RT 8.02 번호 부여 소스 기준이며 원본 자산은 공개 저장소에 넣지 않는다.

| 확인 대상 | 확인한 사실 | 이번 증상과의 관계 |
| --- | --- | --- |
| 투명도 경로 | 원본 1256–1306의 표시 플래그 한 바이트 쓰기와 조건부 QWORD 쓰기 생략을 유지 | 이 경로에 직접적인 RGB 반전 계산은 없다. 표시 플래그가 렌더링에 주는 영향까지 배제할 근거는 아니다 |
| 손전등 그림자 | 원본 `tpflashshadowsdisable` 초기값은 1(928–929). `FLASHLIGHT_SHADOWS_Z_WRITE`는 3인칭이고 정확한 손전등 대상일 때 적용(10014–10045) | 현재 41개 훅에는 이 경로가 없다. 원본 설명(27603–27608)은 캐릭터 자신의 그림자가 빛을 가리는 문제를 방지한다고 명시한다. 원인 후보이며 이번 증상의 확정 원인은 아니다 |
| 손전등 위치 | 원본의 `FLASHLIGHT_ALT_WRITE`는 3인칭 광원 좌표를 별도로 계산(9761–9873) | 현재는 손전등 플래그 입력만 받고 이 좌표 보정은 하지 않는다 |
| 밝기 감소 제한 | 원본 `limittplightfade` 기본값은 1(733–734). `OLD_HOUSE_BRIGHTNESS_READ`에서 3인칭 값을 제한(10198–10226) | 현재 미이식. 캐릭터만 어두운 현상을 직접 설명하는 근거는 아직 없다 |

기존 장비 바이트 진단에는 손전등 그림자 위치 `0x2DEE559`, 밝기 읽기 위치 `0x2E865D7`의
디스크/메모리 단일 매칭과 원본 바이트 일치가 있다. 따라서 이 경로를 이식하기 위해 별도
주소 검색용 Probe를 다시 받을 필요는 없다. 다만 그 기록은 현재 화면의 원인 증거가 아니다.

이번 확인에서 기존 모델 결정 검사 10개와 실제 런타임 어댑터 검사 1개를 다시 실행해 통과했다.
이는 분기·쓰기 범위·레지스터 결과 검사이며 화면 색이 정상이라는 검사는 아니다.
현재 `native_*.jsonl`은 훅 호출/적용 수·상태·좌표·실패·FPS를 기록하지만
재질, 노멀, 최종 픽셀이나 그림자 결과를 기록하지 않는다. 현재 실행 로그만으로 색 반전의
원인을 확정할 수 없으며, 예전 Explore 로그로 새 Native 화면을 판정할 수도 없다.

다음 판별 자료는 현상이 보이는 스크린샷 한 장과 당시 손전등 사용 여부다.
기존에 관찰한 범위에서 밝은 장소에서도 같은지만 알면 후보를 더 줄일 수 있다.
손전등과 무관한 밝은 장면에서도 동일하다면 손전등 그림자 가설의 우선순위를 낮추고
모델/재질 표시 경로를 조사한다. 손전등과 연동된다면 원본의 정확한 대상 비교를 유지한
그림자 경로 한 가지로 비교 시험을 구성한다. 원인이 구분되기 전에는 여러 조명·재질
변경을 묶어 해결책으로 배포하지 않는다. 이번 변경은 문서에 한정되며 DLL은 0.1.0 그대로다.

## 2026-10-18 후속 반영 — 0.1.1

사용자의 반영 요청으로 위 후보 중 `FLASHLIGHT_SHADOWS_Z_WRITE` 경로만 추가했다.
원본 기본 설정처럼 3인칭에서 `[rdi+0xC8] == flashflagadd-0x448`일 때만
DWORD 정수 9999를 쓴다. float 변환이 아니며 레지스터·플래그·XMM은 변경하지 않는다.
`FLASHLIGHT_WRITE`가 실제로 손전등 주소를 수집하기 전, 1인칭, 로딩/필수 상태 미준비,
주소 불일치/오버플로/쓰기 실패에는 원래 명령을 실행한다. F6 OFF의 기존 통과 경로도 유지한다.
스냅샷의 `flashlight_shadow_calls`/`flashlight_shadow_applied`는 훅 호출/적용 누적 수다.
대상 주소 식별용 SDK 호출이나 추가 메모리 탐색은 없다.

새 실제 런타임 검사는 훅이 없는 0.1.0에서 실패한 뒤 구현 후 통과했다. 원본 생산자로
주소를 얻어 정확한 4바이트 쓰기, 다른 광원·1인칭·미준비 통과, 대상 재획득,
쓰기 실패, 정수/float 구분, 레지스터 보존과 진단 집계를 검사한다.
기존 사이트 검사는 새 위치까지 원본 명령 경계와 실제 MinHook 재배치를 검사한다.

이번 변경은 원본의 누락 경로 이식이며 검은 화면 문제의 해결 확정이 아니다.
손전등 밝기·색상·위치, 환경 조명 감소 제한과 모델 재질은 기존 버전 그대로다.
업데이트/시험 방법은 [동봉 설명서](../diagnostics/native/README_KO.md)를 따른다.

## 0.1.2 근접무기 자동 전환 체크박스

원본 `fpmeleeflag`를 `Auto-Disable with Melee Weapons` 체크박스로 노출했다.
원본 번호 부여 소스 27390–27395의 설명과 기본값을 따른다. 공격 버튼이 아닌
근접무기 장착 조건이며, OFF는 해당 조건만 해제한다. 다른 시점 전환과 무기별 예외는 유지한다.
설정은 원자적 요청으로 작업 스레드에 전달하고 런타임 잠금 안에서 옵션 한 바이트만 변경한다.
게임 정책은 다음 기존 정책 훅에서 반영하며, 강제로 전환 상태나 다른 차단 원인을 지우지 않는다.
F6 재활성화 시 원본 기본 상태를 초기화한 뒤 저장된 사용자 선택을 다시 적용한다.

설정 파일 `settings.cfg`는 작업 스레드가 시작할 때 한 번 읽고, UI 변경이 있을 때만 쓴다.
임시 파일 전체 쓰기와 flush 성공 후 교체하며 실패하면 이전 파일을 보존한다.
저장 중 추가 변경은 별도 요청 번호로 유지한다. 저장 실패 때 게임 동작은 현재 선택을 유지하고
메뉴에 실패를 표시한다. 같은 실패를 20ms마다 반복해서 기록/저장하지 않는다.
설정 파일 누락·잘못된 형식은 원본 기본 ON으로 시작한다. 설치·복구는 이 파일을 보존한다.

UI는 기존 Explore 브리지와 같은 고정 Lua 5.4.3 core 연결을 사용하고 DLL 내부의 짧은
`re.on_draw_ui` 콜백으로 메뉴만 그린다. 외부 Lua 파일·`on_frame`·SDK 모델 검색은 없다.
REFramework의 Lua-state-created 콜백과 Lua 잠금을 사용하며, 중복 등록과 Lua 초기화도 처리한다.
UI 등록 실패 시 기존 네이티브 동작과 저장된 옵션은 유지하고 `reframework.log`에 기록한다.
메뉴 위치는 `Script Generated UI > RE7 OTS Native`다.

API/생성 순서는 REFramework 고정 커밋
`d052e8fd3fd41d0a1a33394fcf6e6c19be39b1ee`의
[ScriptRunner.cpp](https://github.com/praydog/REFramework/blob/d052e8fd3fd41d0a1a33394fcf6e6c19be39b1ee/src/mods/ScriptRunner.cpp)를 확인했다.
빌드·패키지는 고정 Lua 아카이브 해시와 실제 C/header 해시도 검증한다.
오프라인 검사는 실제 Lua core의 메뉴 등록/클릭/초기화, 저장 요청 경합·실패·재시작 값,
근접무기 조건만 해제되고 인벤토리 전환은 유지되는지 검사한다.
실제 장비에서 메뉴 표시와 근접공격 조작감은 아직 확인하지 않았다.

## 0.1.3 1인칭 머리와 다른 플레이어 캐릭터

사용자는 RELit 조사와 분리하여 1인칭 눈·코·입 숨김 재시도와 다른 캐릭터 3인칭 진행을 요청했다.
기존 네이티브 카메라/조사 경로를 유지하고 원본 `HEAD_Y_WRITE`의 머리 처리 분기를 추가했다.
`head+0x34/0x74/0xB4/0x2B4`의 Y를 -1000으로 쓰며 같은 명령 블록의 X/Z/W와 CPU 상태를 보존한다.
실제 Head 한 곳만 옮겨 남던 Neck 가중치 부분까지 원본처럼 포함하는 시도다.
원본 손전등의 별도 머리 그림자와 현재 Mia의 별도 머리카락도 정확한 대상 주소에 한해 처리한다.

- `CUTSCENE_AUTOLOOK`의 기존 검증된 머리 주소를 사용한다. 추가 그림자/머리카락 경로는 1인칭일 때만 수집한다.
- `HEAD_Y_WRITE`에서 정확한 대상 주소가 먼저 일치해야 현재 머리 체인과 1.0 모델 마커를 다시 읽는다.
  본편/DLC Clancy는 +0x4BC, 나머지는 +0x53C다. 무관한 오브젝트에는 숨김을 위한 읽기가 없다.
- 포인터 교체·읽기 실패·캐릭터 불일치는 통과한다. 캐시 재수집 시 이전 선택적 주소는 먼저 지운다.
  체인의 역방향 재확인은 변경 감지이며, 게임 오브젝트 수명이나 ABA를 보장하는 잠금은 아니다.
- 3인칭에는 숨김 쓰기와 추가 머리 체인 검증이 없다. SDK 검색·재질 반복 쓰기도 없다.
- F6 OFF이고 숨김 ON일 때는 머리 쓰기와 필요한 원본 생산자 다섯 경로만 C로 전달한다.
  다른 사이트는 확장 상태 저장/C 호출 전에 원래 명령으로 통과한다. 기존 훅과 트램펄린은 유지한다.
- 메뉴의 `Hide Head in First Person`은 기본 ON이다. 예전 한 줄 설정은 근접무기 값을 보존하고
  새 옵션을 ON으로 읽는다. 두 체크박스 요청은 원자적 필드 갱신으로 서로 덮어쓰지 않는다.
- 복원은 게임의 다음 정상 transform 쓰기에 맡긴다. 임의의 오래된 좌표를 되쓰지 않는다.

이미 포함된 여덟 캐릭터 구분과 기본 허용 정책을 회귀 검사했다.
[캐릭터별 지원 및 외부 모델 조건](NATIVE_CHARACTERS_KO.md)을 참고한다.
Ethan 전용 모델로 다른 캐릭터의 머리를 생성하지 않으며, 임의 캐릭터 교체 기능을 추가하지 않았다.

로그는 실제 적용 수 `head_applied`(머리/그림자/현재 Mia 머리카락), `head_target`,
캐릭터 원시 ID/비트/생산자 관측 여부와 모델 판별값을 기존 250ms 스냅샷에 추가한다.
추가 로그를 위해 게임 메모리를 검색하지 않는다. F6 OFF의 `ready=false`는 전체 카메라 입력이
수집되지 않았다는 뜻일 수 있다. `model_marker=null`은 기존 정책 생산자에서 미수집 상태이며,
숨김 적용 직전의 별도 검증은 계속 필요하다. 초기 Joe 분기는 실제 관측 ID와 구분한다.

호스트 검사는 모든 캐릭터와 네 가지 transform, 원본 그림자 두 체인, 현재 Mia 머리카락,
모델 마커/읽기 실패/주소 교체/오버플로, 전체 명령 효과, F6 OFF의 카메라 무변경과
3인칭의 숨김 무변경, 실제 어셈블리 48개 사이트의 head-only 통과를 검사한다.
배포 당시에는 실제 얼굴 숨김 효과가 미확인이었다. 2026-10-19 사용자가 1인칭 얼굴 숨김을
확인했다고 보고했다. 다른 캐릭터, 전 구간 복귀 애니메이션과 FPS 확인은 남아 있다.
피격 혈액 효과 지연, 수동 손전등 옵션과 원본의 모든 디버그/선택 기능을 이식한 것은 아니다.

## 2026-10-19 손전등 그림자 코드 제거 필요성 검토

결론은 현재 유지다. 0.1.1에서 검은 캐릭터 원인을 조사하며 추가한 실행 변경은
`FLASHLIGHT_SHADOWS_Z_WRITE` 한 경로다. 원본 RT 8.02의 `tpflashshadowsdisable`은
기본값 1이며, 원본 설명은 3인칭에서 플레이어 자신의 그림자가 손전등 빛을 가리는 현상을
방지하기 위한 것이라고 명시한다. RELit 증상의 해결 효과와 별개로 원본 기능으로서 목적이 있다.

| 경로 | 현재 역할과 범위 | 판단 |
| --- | --- | --- |
| `flashlight_shadow_write` | 원본이 식별한 게임 손전등의 그림자를 3인칭에서 억제. 해당 손전등의 그림자 전체에 영향 | 유지. 제거하면 기본 손전등 자기 그림자 문제가 다시 드러날 가능성 |
| `native_head`의 얼굴/머리 그림자 처리 | 1인칭에서 확인된 목·머리·헬멧·그림자·현재 Mia 머리카락 위치 처리 | 유지. 사용자 얼굴 숨김 확인 완료 |
| RELit 색상·재질·밝기 강제 보정 | Native에 추가한 코드 없음 | 제거 대상 없음 |

손전등 경로는 1인칭/F6 OFF, 대상 주소 불일치, 필수 입력 미준비, 쓰기 실패 시 원래 명령으로
통과한다. RELit 추가 조명은 검색하지 않는다. 이 경로에 SDK 모델/재질 순회도 없지만,
훅 실행과 상태 저장 비용은 있으므로 제거로 얻을 실제 FPS 차이를 측정 없이 단정하지 않는다.
원본 손전등 그림자를 복원하려는 요구나 이 경로의 부작용이 확인되면 별도 ON/OFF 옵션을
검토할 수 있다. 현재는 삭제나 새 옵션 추가 없이 문서와 실기 상태만 갱신한다.

근거는 원본 번호 부여 소스 928–929, 10014–10045, 27603–27608과
`native_runtime.c`, `native_head.c`, 0.1.1 커밋 `260d6aa`의 변경 범위다.
관련 호스트 검사 20개가 통과했으며, 기본 손전등 그림자의 실제 제거 전후 화면이나
다른 캐릭터 화면을 이번 검토에서 새로 시험한 것은 아니다. 배포 DLL은 0.1.3 그대로다.
