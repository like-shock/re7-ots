## 확인한 문제와 판단

이전 코드에서 F6 켜기와 끄기가 동일한 최신 상태값/메뉴 조건을 사용했다. 상태 파일을 읽지
못하는 동안 끄기를 눌러도 요청이 남아, 회복 후 카메라가 다시 켜지는 상황을 재현하고 수정했다.
반복된 LockScene에서 실제 중단 사유가 `PAUSED`로 바뀌는 기록 문제도 재현해 수정했다.

걷기·계단에서의 1인칭 복귀 원인이 이 두 문제였다고 단정하지 않는다. 현재 보유한 사용자 로그는
구형 Observer v0.2.0이며 카메라 정보도 부족하다. 기존 카메라 중단 기준(갱신 시간, 세대,
거리, 위치 변화, 소유권)은 유지했다. 기둥 가림을 직접 판별하는 코드는 없다.

동일한 SDK 모의 트리(머리/중간 객체 + 무관한 자식 60개), 정상 활성 프레임 120회 기준:

| 정상 활성 프레임당 전체 트리 검색 | 8 | 2 |

전체 검색은 약 75%, 컴포넌트 방문은 약 74% 줄었다. 실제 프레임 속도 향상률이 아니다.
이동/재정렬/대상 교체/재질 변경/세대 변경과 캐시 후 추가된 중복 후보의 쓰기 차단을 검사한다.

## 검증과 사용

전체 검사 명령은 `bash diagnostics/test.sh`다. 생성된 실제 autorun Lua를 SDK 모의 환경에서
실행해 만든 JSONL을 Python 요약 도구에 전달하는 통합 검사도 포함했다. 독립 검토와 최종
결과는 [구현 기록](superpowers/plans/2026-10-14-offline-stabilization.md)에 남긴다.
설치·로그 분석 명령은 [한국어 안내](../diagnostics/EXPLORE_README_KO.md)를 참조한다.

전체 Python 검사 103개 중 102개 통과, 원본 비공개 CT가 필요한 선택 검사 1개는 건너뛰었다.
C 핵심 검사 30개와 Observer 시나리오 12개도 통과했다. 독립 검토에서 중대한 문제는 없었다.
로그 도구의 경미한 제한은 남아 있다. 같은 실행/시각의 서로 다른 표본은 분석에서 제외되지만,
`conflicts`에는 전환 이벤트 충돌만 집계된다. 복귀 기록은 상태 전환의 증거이며 실제 화면의
1인칭 전환이나 복원 성공을 단독으로 입증하지 않는다.

실제 게임의 머리 표시·그림자·컬링·성능, 계단 현상의 원인 확인은 남아 있다. 스팀덱을 사용할 수
있을 때 통합본으로 평소 플레이하며 확인하면 된다. 벽 충돌과 3인칭 탄도는 검증된 엔진 연결
근거가 아직 없어 이번 구현 범위에 포함하지 않았다. 별도 모델 파일은 계속 원본 배포처에서 설치한다.
