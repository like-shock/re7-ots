# 원본 네이티브 이식 진행 기록

**최신 진행:** [Native OTS 0.1.0](NATIVE_INTEGRATION_KO.md)은 41개 원본 명령 위치에
카메라·상태·충돌·조사 대상·발사 원점·모델 투명도 처리를 연결한 실제 플레이 시험용
DLL이다. 별도 Probe 실행은 선행 조건이 아니다. **아래 내용은 통합 전 스칼라 이식의
역사 기록이며, 현재 연결 범위는 위 문서를 기준으로 한다.**

2026-10-17. 원본 RT 8.02의 시점·조준·상호작용 제어 이식을 최우선으로 진행한다.
1인칭 눈·코·입 숨김은 선택 기능이다. 이 기능의 추가 최적화나 숨김 성공 여부를
원본 이식의 선행 조건으로 두지 않는다.

## 이번에 구현한 범위

`diagnostics/src/original_scalar.c`는 원본의 스칼라 계산·분기 일부를 C로 옮긴 코드다.
REFramework SDK 호출, 모델 탐색, 머리 숨김, 파일 왕복이 없는 값 기반 함수다.
**아직 게임 훅에 연결하지 않았다. 현재 설치본의 시점이나 성능을 바꾸는 업데이트가 아니다.**

| 원본 경로 | C로 이식한 부분 | 아직 연결하지 않은 부분 |
| --- | --- | --- |
| `HEAD_Y_WRITE` | `stopflag`, `internalfpflag`, TP 토글, FP 조준 옵션의 시점 판단 및 `recentfpflag` 유지 | 상태 생산 훅, 호출 시점; 머리 숨김은 선택 범위 |
| `CAM_WRITES` | OTS/FP 각 축 좌표식, pitch 보정·배율, 수면 높이 예외 | 대상 주소 식별, flycam/잠금, 전체 분기, 무기 가림 전환 |
| `CAM_WRITES` focus | 조준 확대·복귀 증분, 임계값 초과와 완료 순서 보존 | 프레임/시간 기반 증분 생산, 무기·장면에 따른 focus 분기 선택 |
| `FIRING_COOR_WRITES` | 유효한 카메라 XYZ를 발사 원점으로 선택 | 원점 쓰기 훅과 같은 프레임의 카메라 수집 |
| `TP_INTERACTABLE_COORDS` | 같은 OTS 좌표식을 재사용 가능 | 조사 대상·팝업·지역 조건, 실제 쓰기 훅; 일반 A 버튼 보정은 미확인 |

원본은 `fpaimflag=0`이 기본이므로 **조준 자체가 강제 1인칭 조건이 아니다.**
다만 `stopflag`나 `internalfpflag` 등 원본의 의도적인 1인칭 전환은 남는다.
머리 숨김 코드를 제외하면서 이 시점 판단까지 함께 제거해서는 안 된다.
벽 거리 배율은 좌표 계산 입력이며, 이 값만으로 FP 정책을 바꾸지 않는다.

축 계산을 한 번의 공통 벡터 처리로 합치지 않았다. 원본 `CAM_WRITES`는 X/Y를
계산한 다음 Z 처리 중 `pitchmul`과 조준 배율을 갱신한다. 따라서 X가 이전 배율,
Z가 새 배율을 쓰는 순서를 향후 훅에서 그대로 구현할 수 있다. 조사 대상 좌표식은
해당 시점의 기존 배율을 쓰며 자체적으로 갱신하지 않는다.

## 원본 대조 및 제한

- 기준 CT SHA-256: `4154ee807842eb17f51b84272c98c3fdf153082c252f176446aa0cd61fd0686d`.
- 시점 판단 1341–1365, 머리 숨김 시작 1367, 기본 FP 조준 옵션 961–962.
- OTS 좌표식 5621–5640 / 5739–5747 / 6303–6322, FP 좌표식
  5671–5684 / 5773–5775 / 6335–6348, pitch 배율 5807–5813.
- focus 6233–6295, 수면 예외 5749–5765, 발사 좌표 5513–5535,
  조사 대상 좌표식 1957–2026. 행 번호는 고정 CT 원문 기준이다.
- focus의 익명 점프 대상도 보존한다. `guncheckflag=0`의 일반 진입은 높이·플래그
  갱신을 건너뛰며, `nozoomguncheck` 직접 진입은 이를 실행한다. 복귀 중 뒤 거리
  배율이 완료되고 측면 완료 플래그가 아직 없으면, 그 호출은 측면 거리 감소 없이
  완료 플래그만 설정한다. 두 경우 모두 별도 실패 재현 후 수정·회귀 검사했다.
- x87 중간 결과를 `float`로 저장하는 경계와 정수 명령의 부호 없는 float-bit
  비교를 보존했다. `long double`의 64-bit 유효 자릿수를 요구하며 fast-math를 금지한다.
  검사 환경은 x87 확장 정밀도·최근접 반올림이다. 게임 훅은 부동소수점 환경 보존도 필요하다.
- 발사 좌표 읽기 실패는 명시적으로 개선한다. 원본 CT 예외 경로처럼 일부 좌표만
  남기는 대신, 유효한 XYZ 전체가 없으면 게임의 원래 발사 XYZ 전체를 사용한다.
- 기본 설정과 32가지 시점 조합, 좌우 어깨·벽 배율, FP 좌표,
  축 사이 배율 변경, focus 초과·복귀 완료 순서, 수면 경계, 발사 실패를 검사한다.
- 비공개 원본 CT에서 산술 명령을 직접 추출해 실행하는 대조 검사를 추가했다.
  고정 seed의 1,000개 입력 × 6개 식 = **6,000개 결과가 float 비트 단위로 일치**했다.
  별도 Python 계산식을 정답으로 삼지 않는다. CT가 없는 CI에서는 이 대조 검사만 건너뛴다.

이는 계산·정책 검증이며 게임 메모리의 객체 정체성, 실행 순서, 프레임 속도,
상호작용 버튼 위치 또는 조준 플레이 검증이 아니다. 원본 CT와 모델 파일은 재배포하지 않는다.

## 확보한 훅 위치 근거

사용자가 제공한 2026-10-13 진단 로그에서 아래 위치는 디스크/메모리 각각 단일 AOB
검색 결과와 원본 복원 바이트가 일치했다. 실행 파일 SHA-256은
`d550260029b51a580e206b9a12a4eb7f4a1b4dd230bba5defcca81da40597321`이다.

| 제어 지점 | 패치 시작 RVA | 확인된 길이 |
| --- | --- | --- |
| `CAM_WRITES` | `0x2416E64` | 31 bytes |
| `FIRING_COOR_WRITES` | `0x1769D17` | 24 bytes |
| `TP_INTERACTABLE_COORDS` | `0x2417C5C` | 25 bytes |
| `HEAD_Y_WRITE` | `0x2417B13` | 21 bytes |
| `DOF_ORIGIN_ANGLE_WRITES` | `0x176A0CA` | 24 bytes |

로그의 판정은 `BYTE_MATCH_ONLY`다. 주소를 확보했으므로 위치를 처음부터 다시 찾을
필요는 없지만, 현재 실행 파일 검사·명령 보존·대상 객체 구별을 생략할 근거는 아니다.
특히 `CAM_WRITES`와 `TP_INTERACTABLE_COORDS`는 비슷한 바이트를 갖는 서로 다른 위치다.

## 다음 이식 작업

1. 원본의 카메라 주소 수집, 상태 생산과 전체 `CAM_WRITES` 분기·무기 가림 전환을 연결한다.
2. 원본 충돌 거리 제어와 발사 원점·조사 대상 좌표 쓰기를 같은 제어 흐름에 연결한다.
3. Windows x64 훅의 레지스터/명령/부동소수점 상태 보존, 설치·해제와 Explore 동시 실행
   방지를 구현한 뒤 통합본을 만든다. 머리 숨김은 이 목록의 의존성이 아니다.

빌드: `bash diagnostics/original_build.sh`는 Windows x64 object만 생성한다.
`bash diagnostics/test.sh`가 이 빌드와 전체 회귀 검사를 실행한다.
`RE7_CT_FILE=/path/to/re7.CT`를 지정하면 원본 산술 대조도 실행한다.
