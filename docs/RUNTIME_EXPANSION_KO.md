# v0.5.0-dev 통합 구현과 남은 게임 확인

2026-10-14. 사용자의 승인 범위에 따라 실제 Steam Deck 확인이 필요한 기능도 구현했다.
장치 확인을 개발 착수 조건으로 두지 않았다. 네이티브 DLL/프로토콜은 v0.3.0이며 읽기 전용이다.
현재 게임에서 확인된 사실은 몸체 표시, 얼굴 부재, 걷기·계단의 간헐적 1인칭 복귀다.
이번 머리·충돌 기능의 렌더링 성공이나 기존 복귀 원인 해결을 확인한 것은 아니다.

## 구현 범위

| 기능 | 구현한 동작 | 실제 게임에서 남은 확인 |
| --- | --- | --- |
| RT 모델 | 8계열/9부품의 정확한 경로·재질·Head 관절·로컬 계층 식별, 독립 표시값 소유/복원 | 객체 구조, 얼굴/머리카락 표시, 목 연결·그림자·가림 |
| Mia 부품 | 얼굴과 머리카락을 함께 확인, 부품 누락/중복/혼합 거부, 부분 표시 실패 시 숨김 | 실제 분리 객체와 애니메이션 |
| 장애물 | 선택적 중심선 ray, 가까운 접촉 기준 즉시 축소, 초당 최대 1.5단위 외향 복귀 | 벽·기둥·계단·얇은 물체·출발점이 벽 안인 경우·성능 |
| 조준 복귀 | 조준 관측 시 1인칭, 마지막 조준 관측 후 보류 및 진입 보간 시간 설정 | 실제 총·재장전·조준 입력과 화면 지연 |
| 어깨 | F7 한 번 눌러 좌우 전환, 메뉴/포커스/최신성/ON 조건, 값 저장 | Steam Input 배치와 조작감 |
| 실패 복구 | 모델/물리 실패와 무관하게 기존 카메라 복원 실행, 실패 사유/부품/접촉 로그 | 컷신·로딩·DLC별 네이티브 체인과 복원 |

조준은 기존 1인칭 정책을 유지한다. 원본 CT 탄도 후크는 모드별 레지스터·주소 쓰기에 의존하며,
확인된 Lua 탄도 setter가 없다. CT의 가림 관련 바이트도 저자 주석상 의미가 확정되지 않았다.
이를 임의의 메모리 쓰기로 이식하지 않았다. 원본 CT 완전 이식/3인칭 전투 완성은 이 버전의 결과가 아니다.
사용자의 추가 승인 없이 진행할 수 있는 구현·검사는 진행했으며, 실제 장치 관찰만 남긴다.

정확한 전체 경로와 재질 집합은 `diagnostics/lua/model/ethan.lua`의 프로필에 있다.
파일명은 기존 Ethan API와 호환되도록 유지했다. `model/group.lua`가 부품별 Visibility/HeadSession을
구성하며, 한 부품의 원래 표시값을 다른 부품에 재사용하지 않는다. 모든 show 직전 전체 계열을 다시
확인한다. 트리128노드/깊이12 제한을 넘으면 중단한다. 새 플레이어 세대에는 옛 복원값을 적용하지 않는다.

기존 Ethan 단독 모드는 그대로 사용할 수 있다. 전체 묶음 검색 실패는 0.5초 간격으로 재시도한다.
모델 선택 옵션과 충돌 옵션은 기본 OFF이며 카메라는 실행마다 OFF다. 머리와 카메라 이격 기준0.60은
실측 모델 크기가 아닌 기존 개발 기준이다. 명시적 모델 OFF는 소유한 값의 원래 상태를 복원하므로,
원래 표시된 모델이면 1인칭에서도 보일 수 있다. 모델 제거는 게임 종료 후 외부 관리자에서 한다.

## 물리 API 근거와 제한

[EMV Engine](https://github.com/alphazolam/EMV-Engine) 커밋
`a8a89961fde640d542afc72bd66fd8e12f3b82b3`의 `Gravity Gun/reframework/autorun/Gravity Gun.lua`를
일차 코드 근거로 사용했다. `via.physics.System.castRay`, `CastRayQuery/Result`, AllHits/NearSort,
FilterInfo, ContactPoint.Position, Collidable.GameObject 및 Transform 부모 조회 계약을 확인했다.
RE7 레이어는 참조 코드의 경험적 집합0~32 중7·18을 제외한31개, group0/mask2다.
벽 전용 마스크나 모든 렌더링 물체를 포함한다는 근거는 없다.

`explore/physics.lua`는 게임 콜백 안에서 새 query/result를 만들고 콜백 내에서만 사용한다.
각 레이어의 결과를 비운 뒤 다음 조회로 진행하며 Lua에는 숫자 좌표·거리·카운터만 남긴다.
레이어당64개/전체256개 접촉, 부모32단계, 메서드 부모 타입16단계로 제한한다.
자기 플레이어 Transform 또는 그 자식만 제외한다. 소유자 없는 유효 접촉은 장애물로 취급한다.
누락 API, 잘못된 값, 벗어난 접촉점, 순환 부모, 초과 결과는 clear가 아닌 unavailable이다.
31회 조회의 실제 프레임 비용은 미측정이다. 옵션 OFF이면 물리 SDK 호출은 하지 않는다.

[REFramework](https://github.com/praydog/REFramework) 커밋
`d052e8fd3fd41d0a1a33394fcf6e6c19be39b1ee`의 `src/mods/bindings/Sdk.cpp`에서 add_ref와
Lua GC 참조 해제를 확인했고, `scripts/re2_smooth_movement.lua`의 Vector3f 생성 및
`re2_vr_crosshair.lua`의 setRay 호출을 대조했다. 빌린 객체의 강제 해제나 영구 캐시는 사용하지 않는다.

중심선의 가장 가까운 접촉에서 기본0.12단위 여유를 빼고 목표를 축소한다. 여유 거리가0.10미만이면
1인칭을 유지한다. 실패 시 기존 카메라를 복원한다. 충돌 자체로 기존 상태 안정화 타이머를 매번
초기화하지 않아 좁은 공간에서 반복 진입 대기를 줄인다. 이 기능은 sphere/capsule sweep이 아니며,
카메라 가장자리 클리핑·레이어 누락·벽 내부 출발은 실제 엔진 특성에 따라 남을 수 있다.

## 자동 검증과 배포

`bash diagnostics/test.sh`: C core30/observer12, Python/Lua135개 중134개 통과와 선택 CT1개 생략.
실제 Lua5.4에서 운영 코드를 실행하고 SDK 경계를 모의 처리한다. 물리 API 누락/예외/접촉 한도,
자기 충돌체 제외, 가장 가까운 벽, 즉시 축소/제한된 복귀, 모델 숨김 순서, 카메라 복원, 반복 조준,
F7 누름 유지/메뉴/포커스/OFF, 설정 저장/초기화를 검사했다. 새 요구 사항은 RED→GREEN으로 진행했다.
전체모델 구현 중 기존 HeadSession의 복원 실패 반환값 문제도 회귀 검사와 함께 수정했다.
최종 로컬 검증은 제공받은 원본 CT도 연결해 135개 모두 통과했다. 공개 CI는 그 파일 없이 선택1개를 생략한다.
독립 코드 검토에서 중요 결함은 없었다. 경미한 보류 항목: 조준 보류 시간은 마지막 조준 관측을
기준으로 하므로 첫 해제 관측부터 센 시간보다 표본 간격만큼 짧을 수 있다. 기존0.5초 안정화는 유지된다.

[구현·검토 기록](superpowers/plans/2026-10-14-runtime-expansion.md)에 최종 검토와 배포 상태를 남긴다.
`work` 자동 빌드는 설치 ZIP과 소스 ZIP을 만들며 커밋/트리/파일 해시를 포함한다.
자동 검사와 빌드는 실제 RE7 실행·Windows 로더·Steam Deck 렌더링 검증을 대신하지 않는다.
사용 시 [설치 안내](../diagnostics/EXPLORE_README_KO.md)를 따르면 된다.
