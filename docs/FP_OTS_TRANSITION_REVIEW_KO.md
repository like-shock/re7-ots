# 1·3인칭 반복 전환: 원본 모드와 Explore 비교

**후속 수정:** 정지·이동 중에도 반복된다는 추가 보고로 v0.5.9에서 상태 저장 실패 후 갱신 지연을 수정했다.
자세한 재현 근거는 [실기 피드백 문서](GAMEPLAY_FEEDBACK_KO.md)의 v0.5.9 항목에 있다. 아래는 그 수정 전 검토다.

검토일: 2026-10-16. Explore 기준: `4629136` / v0.5.8-dev.

## 결론과 현재 상태

반복 전환은 **실기 해결 확인 전**이다. v0.5.8은 좌표 표시와 머리 처리 비용을 수정했으며,
벽 전환 알고리즘은 v0.5.2의 안정화 처리를 유지한다. 해당 변경 이후 `obstacle.lua`의 차이는 없다.
`core.lua`의 전환/상태 유효성 규칙도 동일하다.

원본은 벽 거리 보정과 자동 1인칭 전환을 분리한다. Explore도 거리를 줄이지만, 확보된 거리가
너무 짧으면 1인칭으로 복귀하는 추가 조건이 있다. 두 구현의 동작은 같지 않다.
또한 제공 로그에는 벽 충돌과 무관한 상태 입력 실패/재검증 전환이 있으므로,
복귀 지연 하나를 늘리는 것으로 모든 반복 전환이 해결된다고 판단할 수 없다.

## 확인한 원본

- 사용자 제공 `re7.CT` SHA-256:
  `4154ee807842eb17f51b84272c98c3fdf153082c252f176446aa0cd61fd0686d`.
- [원본 제작자 배포 설명 및 변경 기록](https://www.nexusmods.com/residentevil7/mods/12),
  v8.01/v8.02와 v7.18 관련 항목을 2026-10-16 확인.
- 원본 실행 파일/게임 장면을 여기서 실행한 결과는 아니다. 아래는 CT 제어 흐름과 제작자 설명의 비교다.
- CT 원문, 모델 파일, 사용자 원본 로그는 저장소에 추가하지 않았다.

## 원본과 현재 구현의 차이

| 상황 | 원본 CT | Explore v0.5.8 |
|---|---|---|
| 뒤쪽 벽 접근 | `tpcamclip` 경로에서 후방·측방·높이 배율을 조절하며 최소 배율을 유지 | 중심선 충돌 결과로 카메라 거리를 줄임. 여유 거리를 뺀 이동 가능 거리가 0.1 미만이면 `FIRST_PERSON_COLLISION` |
| 작은 벽 거리 변화 | `oldwallping` 대비 0.001 미만 변화 무시 및 복귀 버퍼 | 1인칭 진입 0.1 / 이탈 0.2의 서로 다른 경계와 연속 0.4초 여유 확인 |
| 벽에서 멀어짐 | `cczoomoutbuffer`에 따른 단계적 복귀. 기본 0.6, 뒤로 복귀 시간 기본 1초 | 여유 확인 후 최종 이동량을 초당 1.5 게임 좌표 단위로 제한 |
| 벽으로 조준이 막힘 | 별도 `gbflag` 기능. 제공 CT 기본 OFF. 활성화 시에도 `truegbusesfocus=1`이면 집중 시점 사용, 1인칭 전환과 구별 | 일반 벽 검사와 별개 무기 막힘/집중 시점 제어는 아직 없음. 조준 입력은 1인칭 |
| 상호작용·연출·특정 구간 | `stopflag`, `internalfpflag` 및 아이템·퍼즐·장소·FOV 등의 별도 판단 | 검증된 상태의 조준·인벤토리·상호작용과 카메라/플레이어 유효성으로 복귀 |
| 상태 입력 누락 | 게임 내부 명령 후킹에서 직접 읽음. Explore의 상태 JSON 전달 경로는 없음 | nil/읽기 예외는 즉시 1회 재시도. 두 번 실패하거나 입력이 무효/오래되면 복귀 후 재검증 |

원본의 `Firstperson/Thirdperson Transitions` 옵션은 전환 애니메이션 처리와 관계있다.
이 옵션을 끈다는 것이 모든 자동 1인칭 조건을 없애는 것은 아니다.

제작자의 v8.01은 벽에서 뒤로 빠지기 전 지연을 추가했지만, v8.02는 그 지연 옵션을 제거하고
확보된 공간에 따른 복귀 버퍼로 바꿨다. v8.02는 Bedroom 시계 조사 시의 1인칭 깜박임도
별도 수정했다. 이는 원본에도 전환/벽 이동 관련 수정 이력이 있다는 근거이며,
사용자가 겪은 정지 상태 반복 전환과 동일한 버그였다는 근거는 아니다.

동일 내용인 v0.5.0 로그 재업로드는 중복 계산하지 않았다. 샘플 개수는 전환 횟수가 아니므로
`channel=camera` 전환 이벤트를 사용했다. 논리 상태가 ACTIVE여도 카메라가 크게 당겨져
화면상 1인칭처럼 느껴질 수 있으며, 로그만으로 렌더링된 시점을 직접 판정할 수 없다.

## 기존에 반영된 완화와 이번 검토 결과

- v0.5.1: nil/예외 상태 읽기를 대기 없이 한 번 재시도한다. 재시도 성공만으로 입력 유효성
  검사를 건너뛰거나 오래된 상태를 새 상태로 간주하지 않는다.
- v0.5.2: 충돌 경계 흔들림, 짧은 clear 판정, 조회 실패 직후 복귀를 안정화한다.
  최종 목표까지 검사하고, 여유 0.2 이상을 0.4초 연속 확인한 후 복귀한다.
- v0.5.8에서 위 처리의 회귀 검사 45개를 다시 실행해 통과했다:
  `test_obstacle.py` 20개, `test_snapshot_read.py` 4개, `test_explore_lua.py` 21개.
  모의 검증이며 원본/Explore 게임 화면의 비교 테스트가 아니다.

이번 검토에서는 원인 미확정 상태에서 전환 임계값을 다시 조절하지 않았다.
원본의 최소 배율만 복사해 3인칭을 강제하면 현재 중심선 검사에서는 벽 관통이 다시 생길 수 있다.

## 후속 수정 기준

1. 벽으로 인한 거리 조정과 게임 상태 때문에 필요한 1인칭 전환을 계속 구분한다.
2. `FIRST_PERSON_COLLISION`이 반복되는 경우에 원본의 공간 기반 복귀 버퍼를 현재 충돌 검사에
   맞춰 검토한다. 확보된 거리보다 카메라를 더 뒤로 보내는 최소 거리 강제는 적용하지 않는다.
3. `WAIT_NATIVE_INVALID` 또는 `WARMUP` 반복이면 상태 전달/갱신 경로를 먼저 다룬다.
   벽 복귀 시간을 늘리거나 유효성 차단을 제거하는 방식으로 덮지 않는다.
4. 실제 개선 판단은 현재 버전의 전환 이벤트·충돌 결과·상태 읽기 결과와 해당 화면을 대응해 한다.
   현재 확보된 증거만으로 원본에는 문제가 전혀 없다거나 Explore가 해결됐다고 결론내리지 않는다.
