# RE7 OTS Explore v0.5.4-dev — 모델 식별 진단

탐색용 카메라 시제품입니다. 기존 관찰기와 달리 실제 카메라 위치를 바꿉니다. 켜고 평소처럼 플레이하면 상태와 카메라 로그를 자동 기록하므로, 별도 기록 시작은 필요하지 않습니다. 이번 버전의 F7은 어깨 전환입니다.

## 설치

1. 게임을 완전히 종료합니다.
2. 아래 구버전 파일이 있다면 게임 폴더의 `RE7_OTS_backup/`으로 옮깁니다. 보관 폴더는 `plugins/`와 `autorun/` 밖에 만드세요.
   - `reframework/plugins/RE7_OTS_Observer.dll`
   - `reframework/autorun/re7_ots_observer.lua`
   - `reframework/plugins/RE7_OTS_Diagnostics.dll`
   - `reframework/autorun/re7_ots_diagnostic_status.lua`
3. 설치 ZIP의 `reframework/` 폴더를 `re7.exe`가 있는 폴더에 합칩니다.

설치되는 파일은 다음 두 개입니다.

```text
reframework/plugins/RE7_OTS_Explore.dll
reframework/autorun/re7_ots_explore.lua
```

ZIP의 `BUILD_INFO.json`에는 소스 커밋과 버전, `SHA256SUMS`에는 파일 해시가 있습니다.
이 두 안내 파일은 게임 폴더에 복사하지 않아도 됩니다. GitHub 자동 빌드 설치본은 저장소의
`Actions → Offline build and package → 성공한 실행 → Artifacts`에서 받을 수 있습니다.
`re7-ots-<커밋>` 묶음을 풀고 그 안의 `SteamDeck.zip`을 사용하세요. 자동 빌드 파일은 14일간 보관됩니다.

현재 작동하는 REFramework, RELit, Proton 및 Steam 시작 옵션을 유지하세요. 새 `dinput8.dll`, Cheat Engine, 별도 실행 파일은 필요하지 않습니다. v0.2.1 카메라 수정본을 먼저 설치할 필요도 없습니다.

## 사용

Steam Input 버튼 하나에 키보드 **F6**을 지정하세요. 예전 F8 버튼을 F6으로 바꿔도 됩니다. 시작할 때 카메라는 항상 OFF입니다. 세이브를 불러오고 REFramework 메뉴를 닫은 상태에서 F6을 짧게 누르면 켜지며, 다시 누르면 꺼집니다. 끄기 입력은 상태 갱신 중단·메뉴 열림·포커스 이탈 중에도 유지되며, 상태가 회복돼도 자동으로 켜지지 않습니다.

메뉴의 `Script Generated UI → RE7 OTS Explore v0.5.4-dev`에서도 `Exploration camera (F6)`를 켤 수 있습니다. `Script Generated UI`는 REFramework 기본 메뉴에 있는 항목입니다. 메뉴가 열려 있는 동안은 적용을 잠시 멈춥니다. `Distance`, `Shoulder`, `Height`로 거리를 조절하고 `Swap shoulder (F7)`로 어깨 방향을 바꿉니다. Steam Input에 F7을 추가 지정하면 플레이 중에도 전환할 수 있습니다. F7은 카메라 ON·최신 상태·게임 포커스·메뉴 닫힘 조건에서 한 번씩 작동합니다. 조절값과 기능 옵션은 저장되며 카메라 ON 상태는 저장되지 않습니다.

조준·인벤토리·상호작용 신호, 로딩 중 잘못된 값 또는 게임 포커스 이탈을 감지하면 적용을 멈춥니다. 정상 상태가 0.5초 이상 안정되면 다시 진입합니다. `Aim release hold (seconds)`는 마지막으로 조준이 관측된 시점부터 복귀를 보류하는 시간(기본 0.5초, 0~1.5초)이며, 0으로 낮춰도 기존 안정화 조건은 유지됩니다. `Camera return blend (seconds)`는 카메라가 뒤로 이동하는 시간(기본 0.15초, 0.05~0.8초)입니다. 조준 시 1인칭을 사용하며, 상태 샘플링에 따른 약 100ms와 스케줄링 지연이 있을 수 있습니다. 완전한 전투·연출 대응은 아직 확인하지 않았습니다.

처음에는 잠시 `VALIDATING`이 표시됩니다. 기존 사용자 로그에서 확인한 실행 파일 SHA-256과 PE 정보에 맞는 빌드만 동작합니다. 게임 업데이트 등으로 `UNSUPPORTED`가 표시되면 해시 제한을 바꾸지 마세요.

| 표시 | 의미 |
|---|---|
| OFF | 사용자가 끈 상태 |
| WARMUP / WAIT / PAUSED 계열 | 상태 또는 카메라가 준비될 때까지 대기 |
| ENTERING / ACTIVE | 위치 적용 진입 / setter 호출 후 좌표 확인 성공 |
| FAULT 계열 | 복구 실패 또는 다른 위치 변경과의 충돌 감지. 자동으로 OFF 유지 |
| ERROR 계열 | 설정이나 로그 파일 오류 |

`Last fallback`에는 최근 자동 중단 사유가 남습니다. `ACTIVE`는 카메라 좌표 확인 결과입니다. 렌더링된 화면의 품질을 판정하는 표시가 아닙니다. 다른 카메라 변경과 충돌하면 현재 외부 위치를 덮어쓰지 않고 OFF로 멈춥니다. 같은 문제가 계속되면 켜기를 반복하지 말고 그 상태의 로그를 전달해주세요.

## RT 머리 모델 (선택)

게임 종료 상태에서 [원본 배포처](https://www.nexusmods.com/residentevil7/mods/86?tab=files)의
**Ethan with Head RT** 또는 **Third Person Full Model Placeholders RT**를 Fluffy Mod Manager로
따로 설치합니다. 구형 DX11용 파일과 구분하세요. Explore ZIP에는 모델이 들어 있지 않습니다.

이미 모델이 표시된다면 다시 설치할 필요가 없습니다. Fluffy 없이 설치할 경우 모델 압축의
안쪽 `natives/` 폴더를 `re7.exe` 옆에 놓고 REFramework의 `Loose File Loader → Enable Loose File Loader`를
켠 뒤 게임을 다시 실행합니다. 폴더가 지원되지 않는 REFramework 버전은 이 방법을 사용할 수 없습니다.

REFramework의 Explore UI에서 `RT head model (experimental)`을 켭니다. 전체 모델 묶음을
설치했다면 `Use full RT model pack (all supported characters)`도 켭니다. 두 옵션 모두 처음에는 OFF입니다.
전체 묶음은 Ethan·Chris·Joe·Mia 2종·Clancy 2종·Zoe의 8개 계열에 대한 바인딩을 포함합니다.
Mia의 한 계열은 얼굴과 머리카락을 별개 부품으로 관리합니다. 필수 부품 누락이나 중복,
혼합 모델을 발견하면 표시하지 않습니다. DLC의 네이티브 상태 읽기와 실제 렌더링까지 검증한 것은 아닙니다.

설정은 저장됩니다. 이후 메뉴를 닫고 F6으로 탐색 카메라를 켜면, 카메라 이동과 머리 이격 거리를
확인한 뒤 머리 표시를 요청합니다. 카메라를 끄거나 자동으로 1인칭 복귀할 때는 먼저 숨깁니다.
스크립트 리셋 때도 머리를 숨겨 둡니다. 몸체나 관절 위치는 수정하지 않습니다.

v0.5.3은 얼굴·눈·머리카락이 1인칭에 남는 보고에 대응해, 머리 오브젝트의 DrawSelf와 함께
검증된 머리 재질 각각의 `MaterialsEnable`도 끕니다. 3인칭 복귀와 옵션 해제 시에는 각 재질의
원래 활성값을 사용하므로, 원래 꺼져 있던 재질을 임의로 켜지 않습니다. 모델 파일 재설치는 필요 없습니다.

v0.5.3 실기 로그에서는 모델 선택이 `WAIT_MODEL_AMBIGUOUS`에서 중단되어 재질 숨김이
실행되지 않았습니다. **v0.5.4는 이 중단 원인을 구분하는 진단 빌드이며, 얼굴 잔존 수정 완료본은 아닙니다.**
기존 설치 방법대로 파일을 덮어쓰고 저장된 머리 제어 옵션을 유지한 채 문제를 재현하면 됩니다.
새 옵션을 켤 필요는 없습니다. 문제 직후 게임을 종료하고 `play_0.jsonl`, `play_1.jsonl`을 함께 전달해 주세요.

`Head binding detail`과 자동 로그에는 다음 구분이 추가됩니다.

- `MULTIPLE_MESH_COMPONENTS`: 한 오브젝트의 메시 수, 서로 다른 메시 수, 최대 4개 메시 식별값.
- `MULTIPLE_HEAD_OBJECTS`: 중복 판단을 유발한 두 머리 후보의 오브젝트·메시 식별값. 전체 후보 수는 아닙니다.
- `COMPONENT_ARRAY_*`: 배열 없음, 접근 API 누락, 잘못된 길이, 빈 원소 등의 구체적 중단 위치.

기존 중복 거부 조건은 유지합니다. 실제 부품 바인딩이 실패했으면 상위 표시도 `WAIT_MODEL_*`을
보여 주며, 계열 이름만으로 `MATCHED`를 표시하지 않습니다.

`Head: VISIBLE/HIDDEN`은 DrawSelf 및 재질 활성값 확인 결과입니다. 최종 화면이 검증됐다는 뜻은 아닙니다.
`WAIT_MODEL_*`은 경로·재질·객체 구조·API가 조건에 맞지 않아 대기 중인 상태이며,
`WRITE_FAILED`, `OWNERSHIP_LOST`, `TARGET_CHANGED`는 모델 제어를 중단한 상태입니다.
`MATERIAL_재질명:사유`는 특정 재질의 숨김·복원 실패입니다. 기존 숨김 설정값이 바뀌어도
새 재질 제어가 유지되는지 확인하며, API나 대상 확인에 실패한 채 숨김 성공으로 표시하지 않습니다.
모델 오류가 발생해도 카메라의 1인칭 복원은 계속합니다.

로그의 `scene_detail` 레코드 안 `model.parts`에는 재질별 상태·원래 활성값과 마지막 `draw_self`/`effective_draw` 조회가
남습니다. v0.5.4 모델 식별 상세는 별도 `model_binding` 레코드의 `model.diagnostic` 또는
`model.parts.<부품>`에 들어갑니다. 같은 `session`/`run`/`lua_clock_s`로 대응하며, 실패 상세가 있을 때만 기록합니다.
`effective_draw`는 엔진 Draw 값이며 실제 픽셀 판정은 아닙니다. 조회 API가 없으면 생략합니다.
재질별 검증 호출이 추가되므로 실제 Steam Deck 성능 영향과 얼굴 잔존 해결 여부는 아직 미확인입니다.

머리 옵션을 끄면 자신이 소유한 표시값을 처음 값으로 돌립니다. 모델 파일은 계속 설치돼 있으므로
원래 표시된 머리가 1인칭에서도 보일 수 있습니다. 원래 외형으로 돌아가려면 게임 종료 후
Fluffy에서 머리 모델도 해제하세요. 모델이 없는 상태에서는 머리 옵션을 OFF로 두면 됩니다.

사용자가 에단 모델 표시와 어깨 전환을 확인했습니다. 다만 v0.5.0 실기 로그에서는 제어 코드가
`WAIT_MODEL_COMPONENTS`에 멈춰 있어 자동 숨김/표시까지 확인한 것은 아닙니다. v0.5.1은
REFramework 배열을 일반 Lua 테이블로 가정하던 부분을 수정했습니다. 자동 숨김·목 연결·그림자·성능은
아직 게임에서 확인하지 않았습니다.

## 장애물 거리 조정 (선택)

`Obstacle avoidance (experimental center ray)`를 켜면 원래 카메라와 목표 위치 사이의
중심선을 검사합니다. 벽 등 접촉 지점에서 `Wall clearance`(기본 0.12, 범위 0.03~0.3)만큼
앞으로 카메라를 당기고, 공간이 확보되면 초당 최대 1.5만큼 뒤로 복귀합니다. 거리는 게임 좌표 단위입니다.
자기 플레이어의 하위 충돌체는 제외하며, 매우 좁으면 `FIRST_PERSON_COLLISION`으로 1인칭을 유지합니다.
API·접촉 정보가 불완전하면 `WAIT_COLLISION_*`으로 대기합니다. 머리는 카메라가 가까우면 숨깁니다.

v0.5.2는 벽 경계의 작은 흔들림이나 잠깐의 감지 누락으로 FP/OTS가 반복되는 경로를 보완했습니다.
벽 접근에는 즉시 당기고, 1인칭으로 당겨진 뒤에는 더 넓은 여유 공간이 0.4초 연속 확인돼야 복귀합니다.
충돌 조회 오류 후에도 같은 안정화 조건을 적용합니다. 복귀 중에는 속도 제한을 유지합니다.
충돌 옵션이 켜져 있으면 첫 진입에도 이 속도 제한을 적용하므로 `Camera return blend`보다
이동 시간이 길어질 수 있습니다.
카메라 진입 애니메이션 중에도 검사는 항상 원래 위치부터 최종 목표까지 수행합니다.
이 수정은 기존의 상태 읽기·조준·인벤토리 등의 복귀 조건을 변경하지 않습니다.

기본 OFF입니다. 이 기능은 중심선 검사이며 카메라의 폭·가장자리까지 보호하는 체적 검사가 아닙니다.
실제 벽·기둥·계단의 충돌 레이어와 성능은 아직 검증하지 않았습니다. 계단/걷기 중 기존 1인칭 복귀의
원인을 해결했다고 단정하지 않으며 기존 상태 중단 조건을 유지했습니다. `Reset offsets`는 거리·어깨·높이만
초기화하고 모델·충돌·복귀 시간 설정은 보존합니다.

범위는 **탐색 카메라, RT 머리 표시 제어, 실험적 장애물 거리 조정과 전환 조절**입니다.
3인칭 탄도 보정과 모든 연출 장면의 판별은 포함하지 않습니다. 구현·근거·남은 게임 확인 항목은
저장소의 `docs/RUNTIME_EXPANSION_KO.md`에 정리했습니다.

## 이번 피드백 반영과 화면 정렬 실험

v0.5.0 로그에서 충돌 옵션은 꺼져 있었으며, 반복 복귀 7회가 `WAIT_NATIVE_INVALID`로 기록됐습니다.
v0.5.1은 상태 파일 읽기가 실패하거나 nil이면 같은 프레임에서 한 번 더 읽습니다. 두 번 모두 실패하면
즉시 기존 복귀 조건을 적용합니다. 읽힌 상태가 잘못됐거나 오래됐다면 재시도로 무시하지 않습니다.

`Earlier HUD camera (experimental)`은 기본 OFF입니다. 켜면 카메라 위치를 GUI 준비 단계 전에 적용하고,
LockScene에서 다른 코드가 위치를 바꾸지 않았는지 확인합니다. A버튼 표시가 이전 카메라 위치로 계산되는지
확인하기 위한 실험입니다. 같은 상호작용 물체를 보며 OFF/ON 차이를 비교할 수 있습니다. 변경 후 메뉴를 닫으세요.
`WAIT_EARLY_CAMERA` 또는 `FAULT_EARLY_CAMERA_CHANGED`가 나오면 이 옵션을 끄고 F6으로 다시 켭니다.

2026-10-16 실기 결과: Earlier HUD camera는 효과가 없었고, Obstacle avoidance는 완벽하지 않지만
효과가 있었다고 확인됐습니다. Earlier HUD camera는 OFF, Obstacle avoidance는 ON을 유지하세요.
정지 중 반복 전환은 여전히 보고됐습니다. v0.5.2의 충돌 안정화가 해당 실기 전환까지 해결했는지는 미확인입니다.

이 옵션은 게임의 상호작용 선택 방향을 바꾸지 않습니다. 카메라를 옆/뒤로 옮겼기 때문에 생기는 시차와
가운데 조작 기준의 어긋남은 별도 미해결 항목입니다. 벽에서 손이 목 뒤에 나오는 현상도 아직 수정 완료가
아닙니다. 잘못된 팔/몸 메시를 숨기지 않도록 이번에는 손 접촉 IK 목표와 모션 상태를 읽어 기록합니다.
모델 표시·좌우 전환은 다시 확인하지 않아도 됩니다. 기존 모델·충돌 설정은 그대로 보존됩니다.

## 피드백과 로그

좋았던 점이나 불편한 움직임을 간단히 알려주세요. 문제가 있으면 게임을 종료한 뒤 아래 폴더의 `play_0.jsonl`, `play_1.jsonl` 중 존재하는 파일을 함께 보내주세요.

```text
reframework/data/RE7_OTS_Explore/
```

로그는 자동 시작하며 두 파일을 번갈아 사용합니다. 파일당 최대 2 MiB, 합계 최대 4 MiB로 오래된 내용은 덮어씁니다. 문제 직후 종료하면 최근 기록을 보존하기 쉽습니다. `status.json`만으로는 플레이 흐름을 알 수 없습니다. 로그가 없으면 메뉴에 표시된 상태 문구만 알려주셔도 됩니다.

기록에는 좌표, 플래그, 카메라 객체 식별값, 적용·복구 결과와 머리 부품별 제어 상태가 들어갑니다. `camera.collision`에는 충돌 상태·조회 수·접촉 수·거리·실패 사유가 기록됩니다.
0.2초 주기의 표본 외에 상태가 바뀐 순간을 `transition`으로 기록합니다. 엔진 콜백에서는
최대 64개 사건을 메모리에 보관하고 다음 프레임에 파일로 내보냅니다. 큐가 넘친 횟수도 남습니다.
Lua 재실행은 `run`, 전환 순서는 `event_seq`로 구분합니다. 검색 횟수는 모델의 `search`에 기록합니다.
`native_read`는 읽기 시도 수·실패 종류·재시도 후 읽힌 횟수를 기록합니다. `recovered_total`은
파일을 다시 읽었다는 뜻이며 게임 상태가 유효하거나 카메라가 계속 적용됐다는 뜻은 아닙니다.
`phase_probe`는 최대 0.5초에 한 번 카메라 Transform/Camera 관절 위치를 고정된 단계별로 복사하고,
모델 옵션이 켜져 있고 유효한 플레이어 상태일 때 손 접촉 목표 및 모션 플래그를 기록합니다.
SDK 객체는 저장하지 않으며 이 진단에는 쓰기가 없습니다.
v0.5.3부터 `phase_probe`와 재질 상세는 `scene_detail` 레코드에 분리됩니다. 같은
`session`/`run`/`lua_clock_s`의 `sample`과 함께 보면 됩니다. 기존 요약 도구의 전환 집계는 유지됩니다.
화면 투영 행렬이나 A버튼 위치를 직접 측정하는 기능은 아직 포함하지 않습니다.
v0.5.2 전환 사건의 `context.collision_last`는 마지막 충돌 조회 시각·결과와 복귀 보류 상태를 포함합니다.
과거 조회 결과일 수 있으므로 `lua_clock_s`를 사건 시각과 함께 확인합니다. `stabilization`에는
보류 이유와 연속 여유 공간 확인 시작 시각이 남아 상태 읽기 실패와 충돌 복귀를 구분할 수 있습니다.

개발 PC에서 Python 3으로 두 로그를 함께 요약할 수 있습니다. 스팀덱에 분석 도구를 설치할 필요는 없습니다.

```bash
python3 diagnostics/tools/summarize_play_log.py play_0.jsonl play_1.jsonl
# 다른 도구에서 읽을 JSON 출력
python3 diagnostics/tools/summarize_play_log.py --json play_0.jsonl play_1.jsonl
```

같은 사건의 중복을 제거하고, 실행별 복귀 사유·머리 오류·기록 누락을 집계합니다.
구버전 로그는 표본 사이 변화만 표시하며, 기둥이나 계단이 원인이라고 추정하지 않습니다.
같은 실행·시각의 표본 상태가 충돌하면 제외하고 충돌 1건으로 집계합니다. 이 구간을 이어 붙여
상태 전환을 추정하지 않습니다. 중단/복귀 요청에는 복원 실패도 포함될 수 있으므로 실제
1인칭 화면으로 돌아왔다는 의미는 아닙니다.
native 값과 카메라 값은 서로 다른 시점의 관찰입니다. 모니터는 한 게임 실행당 최대 12시간 동작합니다.

제거하려면 게임 종료 후 이번에 추가한 DLL/Lua 두 파일만 밖으로 옮기세요. 실행 중 DLL 교체나 재로드는 하지 마세요.

## 개발 검증

실제 Lua 5.4에서 카메라·모델 코드를 실행하고 SDK/파일 경계를 모의 처리합니다. 몸체·다른 캐릭터
보존, 중복·교체 대상 거부, 전환 순서, 쓰기 실패와 카메라 복구를 검사합니다. C 핵심 검사와
기존 관찰기·네이티브 모니터 회귀 검사도 함께 실행합니다. 네이티브 DLL/프로토콜은 v0.3.0이며
이번 버전에서 바꾸지 않았습니다. 자동 검사 통과는 실제 렌더링 성공을 뜻하지 않습니다.
