# RE7 OTS 상태 관찰기 v0.2.1 — 설치 및 실기 시험

v0.2.0 설치 사용자는 `OBSERVER_CAMERA_FIX_KO.md`의 Lua 한 파일 교체 및 짧은 재시험 안내를 따르세요. v0.2.1은 카메라 조회 경로만 수정하며, native DLL은 v0.2.0을 유지합니다.

이 버전은 **3인칭 시제품에 필요한 상태를 관찰하는 진단기**입니다. 화면을 3인칭으로 바꾸지 않습니다.
플레이어 좌표·조준·인벤토리의 CT 포인터 경로와 물체 검사 슬롯을 읽고, REFramework에서 현재 카메라 위치·회전을 조회합니다.
이전 v0.1.0의 78개 패턴 검사를 다시 요청하는 버전이 아닙니다.

개발 환경의 빌드·모의 시험과 Steam Deck 실기는 다릅니다. v0.2.0의 사용자 실기 로그 한 세션에서 native 기록과 재획득을 확인했으나 카메라 조회는 전부 실패했습니다. **v0.2.1 카메라 수정본은 실제 Steam Deck 재확인이 필요**합니다.
현재 정상 작동하는 REFramework, RELit, Steam 시작 옵션과 Proton 설정을 유지하세요.

## 1. 설치

게임을 완전히 종료합니다. 기존 두 진단 파일이 있다면 게임 폴더 아래 `RE7_OTS_backup/` 같은 별도 보관 폴더로 옮깁니다.
`plugins/`나 `autorun/` 내부 하위 폴더를 보관 장소로 사용하지 마세요.

- `reframework/plugins/RE7_OTS_Diagnostics.dll`
- `reframework/autorun/re7_ots_diagnostic_status.lua`

새 설치 ZIP의 `reframework/` 폴더를 `re7.exe`가 있는 폴더에 합칩니다. 결과는 다음 두 파일입니다.

```text
reframework/plugins/RE7_OTS_Observer.dll
reframework/autorun/re7_ots_observer.lua
```

`dinput8.dll`, 기존 `reframework` 폴더, RELit 파일은 교체하거나 삭제하지 않습니다.
Cheat Engine, 별도 EXE, 새 런타임 DLL 설치는 필요하지 않습니다.

## 2. 버튼 및 화면

Steam Input의 사용 가능한 버튼에 키보드 **F8**, **F7**을 각각 지정합니다. 기존 REFramework 메뉴 버튼은 유지합니다.
짧게 눌렀다 놓으세요. 길게 눌러도 한 번만 처리됩니다. 게임이 전경일 때만 동작합니다.

| 버튼 | 기능 |
|---|---|
| F8 | 기록 시작 / 진행 중 기록 종료 |
| F7 | 다음 시험 단계로 이동. 마지막 단계에서는 유지 |

REFramework 메뉴의 `Script Generated UI → RE7 OTS State Observer v0.2.1`에서 상태를 봅니다.
설치만으로 기록을 자동 시작하지 않습니다. 세이브를 불러와 조작 가능한 상태에서 **F8**을 누르세요.

처음에는 실행 파일의 SHA-256과 메모리 PE 정보를 확인하므로 `VALIDATING`이 잠시 표시됩니다.
이 검사는 알려진 빌드에만 고정 포인터 경로를 사용하려는 것이며 전체 패턴 재검색은 하지 않습니다.
현재 대상 해시: `d550260029b51a580e206b9a12a4eb7f4a1b4dd230bba5defcca81da40597321`.
업데이트 등으로 다르면 `UNSUPPORTED`로 종료하고 포인터 체인을 읽지 않습니다. 해시 제한을 수동으로 풀지 말고 생성된 로그를 전달하세요.

`Native: RECORDING`과 카메라 파일 기록 상태를 확인합니다. `READABLE_CANDIDATE`는 값이 읽혔다는 뜻입니다. 올바른 플레이어·조준·카메라임을 확인했다는 뜻은 아닙니다.

## 3. 한 번의 짧은 시험

가능하면 3~5분 안에 다음 순서로 진행합니다. 없는 무기나 아직 접근할 수 없는 물체를 찾으러 갈 필요는 없습니다.
단계를 바꾸기 **직전 F7을 한 번** 눌러 라벨을 바꿉니다. F7 자체가 실제 행동을 감지하거나 검증하지는 않습니다.

| 단계 표시 | 행동 |
|---|---|
| STILL | F8 시작 후 5초 정도 정지 |
| MOVE | F7 → 앞뒤·좌우로 약 10초 이동 |
| LOOK | F7 → 제자리에서 시점만 약 10초 회전 |
| AIM | F7 → 가능하면 조준·해제를 3회. 사격은 필요 없음 |
| INVENTORY | F7 → 인벤토리를 열고 3초 기다린 뒤 닫기, 2회 |
| EXAMINE | F7 → 가까운 물체를 검사하고 종료. 불가능하면 건너뛰기 |
| RELOAD | F7 → 세이브 다시 불러오기 또는 메뉴 복귀 후 불러오기 |
| AFTER_RELOAD | 조작 가능해지면 F7 → 정지 후 이동·회전 10초 |

끝나면 **F8을 누르고 `STOPPED`가 표시될 때까지 기다린 뒤** 게임을 정상 종료하세요.
건너뛴 항목은 로그 전달 시 알려주세요. 단계 표시만으로 해당 행동을 수행했다고 판정하지 않습니다.
로딩/일시정지 중 카메라 샘플이 없거나 NULL/UNKNOWN이 나오는 것은 가능한 관찰 결과입니다.

한 세션은 최대 15분 또는 9,000개 native 샘플입니다. 크기 제한은 파일당 16MiB이고 한 실행에서 최대 4세션입니다.
상한에 도달하면 `LIMIT`으로 종료합니다. 더 필요하면 게임을 재시작하세요. 의도적으로 상한에 도달시킬 필요는 없습니다.

## 4. 전달할 파일

```text
reframework/data/RE7_OTS_Observer/
```

동일한 세션 이름으로 끝이 다른 두 파일이 생성됩니다.

```text
re7_observer_..._native.jsonl
re7_observer_..._camera.jsonl
```

두 파일을 첨부하거나 해당 폴더를 ZIP으로 묶어 보내주세요. `status.json`만으로는 시계열 분석이 되지 않습니다.
카메라 파일이 생성되지 않았다면 native 로그와 메뉴에 표시된 카메라 상태를 알려주세요.
세션 파일명은 기기의 로컬 시각과 단조 증가 시간으로 생성되므로 한국 시각과 다를 수 있습니다.

로그에는 사용자 이름·계정·전체 메모리 덤프를 넣지 않습니다. 좌표, 플래그 후보, 객체 식별 주소, 시각과 시험 라벨을 기록합니다.
Native와 카메라는 서로 다른 시점의 관찰입니다. `native_seq`는 가장 최근에 읽은 native 상태를 가리키며 동시 스냅샷을 뜻하지 않습니다.

## 5. 상태 해석과 문제 발생 시

| 표시 | 의미 / 대응 |
|---|---|
| READABLE_CANDIDATE | 값 읽기 성공. 실제 행동과 대조해야 함 |
| NULL_LINK | 체인 중간 또는 루트가 0. 로딩·메뉴에서 가능 |
| READ_FAILED / INVALID_POINTER | 읽지 못한 단계 기록. 다음 샘플에서 새로 시도 |
| LINK_CHANGED | 읽는 도중 링크 변경을 감지하여 이번 값을 폐기 |
| INVALID_VALUE | 비정상 좌표/숫자/0·1 이외 플래그. 정상 상태로 해석하지 않음 |
| UNKNOWN_* | 카메라 없음, 조회 API/타입 미지원, 상태 파일 문제 등. 획득 성공으로 취급하지 않음 |
| UNSUPPORTED | 대상 빌드 확인 실패. native 로그의 원인 확인 |
| ERROR_* / ERROR | 파일 생성·쓰기·조회 문제. 성공 기록으로 취급하지 않음 |
| STOPPED | 사용자가 기록 종료. 관찰 대상의 의미 검증 완료가 아님 |
| LIMIT | 시간·샘플 수·파일 크기 제한으로 종료 |

게임 충돌이나 뚜렷한 성능 저하가 생기면 게임을 종료하고 새 DLL/Lua **두 파일만** 별도 보관 폴더로 옮기세요.
기존 REFramework·RELit은 그대로 둡니다. 필요하면 앞서 보관한 v0.1.0 두 파일을 원래 위치에 되돌릴 수 있습니다.
DLL은 게임 종료까지 유지되므로 실행 중 교체·제거·플러그인 재로드를 하지 않습니다.
Lua 스크립트만 재설정하면 현재 카메라 파일을 닫고 기존 파일을 보존합니다. 이어서 기록하려면 F8로 종료 후 새 세션을 시작하세요.

## 6. 관찰 범위의 한계

CT의 물체 검사 코드는 같은 슬롯을 16비트/32비트로 다르게 검사합니다. 따라서 `slot_hex`, `ct_low16_nonzero`, `ct_low32_nonzero`를 모두 기록하며 단일 확정 boolean으로 바꾸지 않습니다.
재획득 세대 번호는 읽기 실패 후 회복 또는 관찰한 포인터 경로 변경을 나타냅니다. 주소 재사용(ABA), 객체 종류, 재로딩 자체를 증명하지 않습니다.
카메라 API가 반환한 transform과 CT 카메라 수정 대상의 동일성은 아직 미검증입니다.
게임 setter·직접 메모리 쓰기·인라인 후크를 사용하지 않습니다. REFramework의 정상 getter/객체 래퍼 및 내부 참조 카운트 처리는 사용합니다.
