# RE7 OTS Native 0.1.12 — 원본 네이티브 이식 실험 빌드

원본 RE7 Third-Person OTS RT 8.02 CT의 카메라와 조사 대상 처리를 네이티브 코드로
옮긴 **실제 3인칭 플레이 시험용 빌드**입니다. 실행 직후에는 3인칭 카메라가 꺼져 있으며,
**F6으로 3인칭을 켜고 끄고, F7로 어깨 방향을 바꿉니다.** 진단 로그는 자동 기록됩니다.

0.1.12는 다른 광원을 처리할 때 Fullbright 대상이 지워져 조명 범위 보정이 빠지는
이식 오류를 수정합니다. 밝기·RGB·조명 범위 설정값은 기존과 같습니다. 보고된
회전 시 원거리의 각진 밝은 경계가 사라지는지는 실제 게임에서 확인해야 합니다.

설치된 모델 파일은 그대로 사용합니다. 0.1.10은 Mia 머리카락·강제 화면 필터·Fullbright·컨트롤러 단축키 설정을 추가합니다.
0.1.11부터 Fullbright를 켜면 F6을 끈 일반 1인칭에서도 유지됩니다.
머리 숨김·컨트롤러 단축키를 꺼도 독립적으로 작동하며, 게임을 다시 시작해도 설정이 유지됩니다.
Fullbright 체크를 해제하면 원래 조명으로 돌아갑니다. 로딩 중에는 일시 중지합니다.
기존 1인칭 얼굴 숨김은 사용자 확인이 완료됐으며 그대로 유지합니다.
얼굴 숨김은 기본 ON이며, F6으로 3인칭을 꺼도 별도 설정에 따라 적용됩니다.
다른 제작자의 모델 파일과 원본 CT는 이 ZIP에 포함하지 않습니다.
이 빌드는 원본 CT 전체 기능·선택 기능의 완성판이 아닙니다. 실제 Steam Deck/Proton에서의
전 구간 화면, 충돌 상황, FPS는 아직 확인할 항목입니다. 사용자는 0.1.0에서 손 문제,
반복 시점 전환과 상호작용 버튼 위치가 해결됐고 가운데 시점도 개선된 것으로 보고했습니다.

## 선택 기능 설정 (0.1.11)

**Script Generated UI → RE7 OTS Native**에서 변경하면 자동 저장됩니다.
예전 1·2·3줄 설정 파일의 근접무기·머리 숨김·광원 대비 선택은 그대로 유지합니다.
새 항목은 아래 기본값을 적용하며 F6 재활성화·게임 재시작 후에도 저장값을 사용합니다.

| 메뉴 | 기본값·동작 |
| --- | --- |
| Hide Mia Hair in First Person | ON. 부모 설정 Hide Head in First Person이 켜져 있을 때만 적용. 이 항목만 끄면 머리 숨김은 유지하고 Mia 머리카락은 표시 |
| Force Custom Screen Shader / Custom Screen Shader | OFF / Main Menu(1). 원본 0~15 필터를 이름으로 선택. 빈사 효과가 우선하며 F6 ON에서 적용 |
| Fullbright | OFF. 검사 대상 조명의 범위·색상과 전역 밝기를 원본 값으로 보정. F6 ON/OFF 모두 적용 |
| Fullbright Red / Green / Blue / Brightness | RGB 255·255·255, 밝기 1. RGB 각 0~255, 밝기 0~10. 끄면 기존 광원 대비 설정으로 복귀 |
| Controller Camera Toggle / Controller Shoulder Switch | 둘 다 Unassigned. 원본 24개 버튼·스틱 방향 중 선택. Camera Toggle은 F6와 같고 Shoulder Switch는 F7과 같음 |

컨트롤러는 지정·로드·재연결 후 **버튼을 놓고 다시 눌러야** 동작합니다. 누른 채로
유지하면 반복 실행하지 않습니다. 카메라와 머리 숨김이 모두 OFF여도 지정한 카메라
단축키로 다시 켤 수 있습니다. 둘 다 같은 버튼으로 지정하면 두 동작이 함께 실행됩니다.
다른 컨트롤러의 연결 상태가 바뀌어도 모든 단축키를 다시 준비합니다. 키보드 F6/F7은
그대로 사용할 수 있습니다. XInput 연결 상태를 확인할 수 없으면 컨트롤러 단축키는
중단하고 `reframework.log`에 이유를 남깁니다.

연결은 작업 스레드의 약 20ms 주기로 관찰하며, 관찰 사이에 분리와 재연결이 모두
끝나는 경우는 구분할 수 없습니다. 입력 생산자가 500ms 동안 호출되지 않은 경우에도
기존 누름 상태를 지웁니다. 실제 Steam Deck의 XInput 연결·버튼 이름·Fullbright 화면은
장비에서 추가 확인해야 합니다. Freecam·시간 속도 변경·무적 기능은 추가하지 않습니다.

## 메뉴·달리기 FOV (0.1.9)

게임 메뉴의 FOV 단계를 원본처럼 `70 + 5 × 단계`로 계산합니다. 별도 커스텀 FOV는
기본 OFF이며, 메뉴를 닫은 뒤에도 마지막 단계 값을 유지합니다. 3인칭 달리기 FOV는
기본 ON, 1인칭 달리기 FOV는 OFF입니다. 최대 증가량은 기본 FOV의 20%이고,
증가 7초·복귀 0.7초의 원본 계산과 조준·컷신 배율 예외를 적용합니다.

REFramework가 FOV를 쓰면 즉시 게임/REFramework에 제어를 돌려주며, 원본 갱신
프레임 3회가 지난 뒤 다시 적용합니다. F6 OFF·로딩·주소 변경·읽기/쓰기 실패에서는
임시 FOV 제어를 해제합니다. 원본 FOV 주소를 새로 관찰하고 실제 대체 쓰기에 성공한
경우에만 본편·NAH·EOZ의 경쟁 쓰기를 막습니다. 0.1.9 당시 총 67개 처리 지점이었습니다.
실제 Steam Deck에서 달리기·조준·REFramework와의 전환 화면은 추가 확인이 필요합니다.

## Not A Hero HUD (0.1.8)

F6 ON에서 NAH의 3인칭 HUD를 원본 기본값으로 숨깁니다. 산소가 정확히 100이 아닌
경우와 필터·야간투시·RAMROD 알림, 시작 구간·폭탄·메인룸·방패·건틀릿의 원본 대화
예외에서는 필요한 표시를 유지합니다. 오염 구역 표시도 갱신합니다. 빈손 초기 표시 오류와
전체 숨김에서 탄약만 표시할 때의 첫 프레임 깜박임 방지를 함께 적용합니다.

로딩 때 대화 순서를 초기화하며, F6·구역 변경·주소 교체 후에는 새 주소를 관찰해야
동작합니다. 쓰기 실패 시 원래 레지스터·스택 경로로 돌아갑니다. 실제 Steam Deck의
NAH 표시와 전환 화면은 추가 확인이 필요합니다. 0.1.8 당시 총 61개 처리 지점이었습니다.

## 화면 피·피격 필터·머리 숨김 지연 (0.1.7)

F6 ON에서 원본 기본값을 적용하며, 추가 설정은 필요 없습니다. 0.1.7 당시 총 58개 처리 지점이었습니다.

| 항목 | 적용 내용 |
| --- | --- |
| 화면 피 | 원본 체력/10 계산과 FP100·TP0 한계를 적용. 상호작용 중 피 숨김 조건이 우선 |
| 피격 필터 | 빈사 필터는 FP0·TP2로 대체. 일반 필터·미사용 값도 원본의 비교 분기 효과를 유지 |
| 머리 숨김 지연 | 상호작용의 피 숨김 조건 동안 2로 갱신하고, 종료 후 원본 갱신 2회까지 머리 숨김을 유지 |
| 주소·상태 확인 | 체력·머리 주소를 다시 확인. 로딩·입력 실패·F6 전환에서 임시 주소와 지연을 지움 |

지연은 초 단위나 모든 모델 호출 횟수가 아니라 원본 TIMESCALE 갱신 순서를 따릅니다.
일반 3인칭에서는 머리를 표시하며, 상호작용 종료의 짧은 원본 지연만 예외입니다.
F6 OFF의 독립 얼굴 숨김 설정은 유지됩니다. 체력 값과 게임 필터 데이터는 직접 수정하지 않습니다.

호스트 검사에서 체력 경계·전체 레지스터/XMM·비교 플래그·주소 교체·기존 얼굴 숨김을
대조합니다. Windows DLL·패키지는 GitHub Actions에서 검사하고 실제 Steam Deck 표시는
별도로 확인합니다.

### Steam Deck에서 확인

1. 같은 세이브에서 F6 ON/OFF를 비교해 화면 피와 피격 효과가 정상인지 확인합니다.
2. 물체 조사·퍼즐을 끝내고 3인칭으로 복귀할 때 머리가 잠깐 가려진 뒤 표시되는지 확인합니다.
3. 세이브 로드·F6 전환 후 피 숨김이나 머리 숨김이 잘못 남지 않는지 확인합니다.

## 3인칭 광원 대비 제한 (0.1.4)

**Script Generated UI → RE7 OTS Native → Limit Light Source Contrast in Third Person**

- **ON (기본값):** 원본 v7.17에 추가된 기능처럼 3인칭에서 조명이 주변 어둠을 과도하게
  강조하는 값을 제한합니다. 게임이 읽는 해당 값의 상한은 원본과 같은 `0.735`입니다.
- **OFF:** 이 제한을 중단합니다. 같은 위치·카메라 각도에서 켜짐/꺼짐을 비교할 수 있습니다.

1인칭과 F6 OFF에서는 적용하지 않습니다. 체크 상태는 자동 저장되고 게임 재실행과 F6 재활성화에도
유지됩니다. 0.1.2/0.1.3의 근접무기·얼굴 숨김 설정은 유지하며 새 제한 옵션만 기본 ON으로 추가합니다.

원본 v7.09의 손전등 그림자 해제와는 별개 기능입니다. 광원 데이터를 직접 수정하지 않고,
원본이 지정한 읽기 지점의 결과만 제한합니다. 장면 전체의 어둠에도 영향을 줄 수 있습니다.
Fullbright, 캐릭터 재질·RGB 보정, RELit 코드 변경은 포함하지 않습니다.
**RELit 조명을 켰을 때 캐릭터가 검게 보이는 문제를 해결했는지는 아직 확인되지 않았습니다.**

### 이번 변경의 최소 확인

1. 검게 보이던 위치에서 RELit 조명을 켜고 F6으로 3인칭을 켭니다.
2. 위치와 카메라 각도를 유지한 채 새 옵션 ON/OFF를 비교합니다.
   캐릭터 색과 주변 화면 밝기를 각각 확인합니다. 차이가 없으면 반복 시험은 필요 없습니다.
3. 옵션 OFF로 한 번 재실행해 설정 유지 여부를 확인합니다. 기본값으로 돌아가려면 다시 ON으로 둡니다.

효과가 없거나 부작용이 있으면 새 옵션을 OFF로 두고, 비교한 장면과 같은 실행의
`native_*.jsonl` 로그를 보내주세요. 추가 조명 자체를 끄는 F8과 이번 체크박스는 다른 기능입니다.

로그의 `light_contrast_calls`는 훅 호출 수, `light_contrast_samples`는 활성 조건을 통과한
읽기 수, `light_contrast_applied`는 실제 상한 적용 수입니다. 마지막 활성 읽기의
`light_contrast_input_bits`/`light_contrast_output_bits`는 부동소수점 비트값을 기록합니다.
OFF/1인칭에서는 마지막 값과 누적 수가 남으므로 옵션·시점과 수치의 **증가량**을 함께 봅니다.
적용 수가 늘어도 캐릭터 색 문제가 해결됐다는 뜻은 아닙니다.

## 1인칭 얼굴 숨김 (0.1.3)

**Script Generated UI → RE7 OTS Native → Hide Head in First Person**

- **ON (기본값):** 1인칭에서 원본이 지정한 목·머리·헬멧 위치를 함께 숨깁니다.

이번 시도는 이전 Explore의 SDK 모델·재질 검색을 사용하지 않습니다. 원본 쓰기 지점에서
현재 머리 주소와 모델 판별값이 맞는 경우에만 처리합니다. 주소·판별값을 확인하지 못하면
숨기지 않습니다. 사용자는 2026-10-19에 1인칭 얼굴 숨김을 확인했습니다.
다른 캐릭터와 전 구간의 표시·성능은 아직 확인하지 않았습니다.

각 DLC의 실제 표시·머리카락·전투·성능은 아직 장비에서 확인하지 않았습니다.

## 근접무기 자동 1인칭 전환 설정 (0.1.2)

REFramework 메뉴에서 다음 항목을 펼칩니다.

**Script Generated UI → RE7 OTS Native → Auto-Disable with Melee Weapons**

- **ON:** 원본처럼 해당 근접무기를 장착한 동안 자동 1인칭 전환을 허용합니다.
- **OFF:** 근접무기 때문에 자동 1인칭으로 바뀌는 조건을 해제합니다.

다음 게임 실행에도 OFF로 시작합니다. F6 재활성화나 REFramework 스크립트 초기화에도 유지됩니다.
설정 파일은 `reframework/data/RE7_OTS_Native/settings.cfg`이며 직접 편집할 필요는 없습니다.
저장에 실패하면 메뉴에 `Could not save`가 표시됩니다. 이때는 현재 실행에만 적용됩니다.

원본처럼 전기톱·조의 주먹 등 일부 무기는 별도 예외가 있어 ON에서도 3인칭일 수 있습니다.
이번 설정은 공통 자동 전환 조건만 조절하며 무기별 예외 설정은 추가하지 않았습니다.
공격 명중과 애니메이션은 장비에서 확인해야 합니다. 가능하면 나이프 등으로 ON/OFF를
비교하고 OFF로 둔 뒤 재실행 시 체크가 꺼져 있는지 확인해주세요.

설정 UI도 DLL에 포함되어 있습니다. 별도 Lua 파일이나 CT 편집은 필요하지 않습니다.
F6/F7은 기존과 같습니다. UI가 보이지 않으면 `reframework.log`를 확인해주세요.

## 유지된 0.1.1 손전등 그림자 변경

캐릭터가 검게 보인다는 보고에 따라 **원본의 3인칭 손전등 그림자 해제 경로 한 가지**를
추가했습니다. 원본이 식별한 손전등에만 적용하며 1인칭과 F6 OFF에서는 원래 명령을 실행합니다.
밝기·색상·광원 위치·재질은 변경하지 않았습니다. 카메라와 상호작용 보정도 그대로입니다.
손전등이 만드는 그림자가 줄어드는 것은 이 변경의 의도된 효과입니다.
후속 사용자 확인으로 검은 표시는 여전하지만 **RELit를 끄면 정상 색으로 돌아오는 것**이
확인됐습니다. 이 네이티브 경로는 게임 기본 손전등만 대상으로 하며 RELit의 추가 조명에는
적용되지 않습니다. 이 그림자 처리에는 별도의 단축키나 메뉴 설정이 없습니다.

### RELit 카메라 추적 조명과 함께 사용할 때

사용자는 **`Enable Shadows`를 이미 끈 상태에서도 검게 보인다**고 추가 확인했습니다.
따라서 이 옵션을 끄는 방법은 해결책에서 제외합니다. RELit OFF 시 정상 색으로 돌아온다는
비교 결과는 유효하지만, 일반 그림자가 원인이라고 확정할 수는 없습니다.

추가 확인에서 사용자는 **F8로 조명만 껐을 때 정상화됐다**고 명확히 했습니다.
따라서 추가 조명의 영향이 발생 조건입니다. 조명 위치, 캐릭터의 직접광 반응,
광량 변화에 따른 게임의 노출 반응 중 무엇이 원인인지는 아직 구분되지 않았습니다.
일반 그림자 옵션을 반복해서 바꾸는 시험은 필요하지 않습니다.
0.1.4에서는 위의 원본 대비 제한을 비교용 옵션으로 추가했습니다.
이 기능과 RELit 증상의 인과관계는 아직 장비 확인 전이며, 재질 강제 보정은 하지 않습니다.
사용 중인 RELit 버전과 실제 렌더링 원인은 아직 확인되지 않았습니다.
[확인한 공개 소스](https://github.com/originalnicodr/RELit/blob/11231ea44ffc92225e7fcf92fd7e9efb64b5f921/RELit.lua).

## 설치

1. 게임을 완전히 종료하고 Steam Deck 데스크톱 모드로 전환합니다.
   REFramework가 이미 설치된 환경을 사용합니다.
2. ZIP을 별도 폴더에 압축 해제합니다. 게임 폴더에 바로 덮어쓰지 마세요.
3. 압축을 푼 폴더에서 터미널을 열고 실행합니다. 경로는 `re7.exe`가 있는 폴더입니다.

   ```bash
   bash install.sh "/게임이 설치된 폴더"
   ```

### 0.1.0 / 0.1.1 / 0.1.2 / 0.1.3에서 업데이트

기존 설치 스크립트로 설치했다면, 게임을 종료하고 아래 명령으로 기존 설치를 복구한 뒤
새 ZIP 폴더에서 `install.sh`를 실행합니다. 설치 기록과 백업 검증을 유지하기 위한 순서입니다.

```bash
bash "/게임이 설치된 폴더/reframework/data/RE7_OTS_Native/install/uninstall.sh" "/게임이 설치된 폴더"
bash install.sh "/게임이 설치된 폴더"
```

직접 DLL만 복사해 설치했다면, 게임 종료 후 기존 DLL을 게임 폴더 밖에 보관하고
새 `install.sh`를 실행하세요. 두 버전의 DLL을 plugins 폴더에 함께 두면 안 됩니다.

설치 스크립트는 파일 해시를 확인한 다음 기존 Explore DLL/Lua, Observer DLL,
Diagnostics DLL, NativeProbe DLL을 백업합니다. 이미 Native DLL이 있으면 중단합니다.
기존 모델과 다른 모드 파일은 이동하지 않습니다. 원본 CT나 다른 카메라 모드는 함께 켜지 마세요.
설치 도중 실패하면 이동한 파일을 복구합니다. 복구가 막히면 출력된 백업 위치를 보존하세요.

## 얼굴 숨김·다른 캐릭터 확인이 필요할 때

1. 기존 세이브의 1인칭에서 `Hide Head in First Person` ON/OFF를 비교합니다.
   F6 OFF와 인벤토리 등 자동 1인칭 구간에서 눈·코·입이 없어지는지 확인합니다.
2. F6 ON 후 머리·몸이 다시 보이고, 기존 카메라·상호작용·FPS에 변화가 없는지 확인합니다.
3. 접근 가능한 다른 캐릭터 구간 하나에서 F6과 1인칭 복귀를 확인합니다.
   모든 DLC를 한 번에 시험할 필요는 없습니다. 현재 Mia는 머리카락도 확인합니다.

문제가 있으면 캐릭터·구간·당시 동작과 같은 실행의 로그를 남기면 됩니다.
`head_applied`는 일반 머리/그림자/현재 Mia 머리카락 순서의 실제 적용 수이며,
`characters`, `character_raw`, `character_observed`, `model_marker`, `assumeheadless`가 판별 상태를 기록합니다.
F6 OFF에서는 일부 정책 입력을 수집하지 않으므로 `ready=false`나 `model_marker=null`만으로
얼굴 숨김 실패라고 판단하지 않습니다. 실제 적용 수와 `head_target`을 함께 확인합니다.

## 기존 카메라 회귀 확인 순서

1. 게임을 시작하고 세이브를 로드합니다. 시작 시 3인칭은 꺼져 있습니다.
2. **F6을 눌러 3인칭을 켭니다.** F7을 눌러 양쪽 어깨 방향도 확인합니다.
3. 가만히 서 있기 → 걷기 → 계단 오르내리기 → 벽 가까이 접근하기를 확인합니다.
   몸이 보이는지, 카메라 위치가 튀거나 벽을 통과하는지, 조작과 FPS가 어떤지 기록합니다.
4. 물체 조사·문서 보기·상자 열기 등 가능한 상호작용을 합니다.
   실제 조사 물체의 위치와 버튼 표시가 맞는지, 종료 후 원래 화면으로 돌아오는지 확인합니다.
   이 이식은 원본이 고른 조사 대상의 좌표를 보정하므로 대상 선택도 검증해야 합니다.
5. 인벤토리를 열고 닫고, 총이 있으면 조준·발사를 확인합니다. 총이 없으면 생략합니다.
6. F6으로 3인칭을 끈 상태와 비교한 뒤 게임을 종료합니다.

진단은 자동입니다. 별도의 기록 시작 버튼이나 90초 Probe 시험 절차는 없습니다.
3인칭이 켜지지 않거나 화면 문제가 있으면 당시 동작과 함께 아래 파일을 보내주세요.

```text
게임폴더/reframework/data/RE7_OTS_Native/native_*.jsonl
게임폴더/reframework.log
```

가능하면 문제가 보이는 스크린샷과 FPS 변화도 함께 남겨주세요.
게임 종료 전에는 DLL을 교체하거나 삭제하지 마세요.

## 이전 구성으로 복구

게임을 완전히 종료한 후 압축을 푼 폴더에서 실행합니다.

```bash
bash uninstall.sh "/게임이 설치된 폴더"
```

Native DLL을 제거하고 백업한 기존 파일을 복원합니다. 자동 진단 로그·설정·모델 파일은 유지합니다.
설치 이후 DLL·백업 파일이 바뀌었거나 복원 위치에 다른 파일이 있으면 덮어쓰지 않고 중단합니다.
설치 시 출력한 `reframework/data/RE7_OTS_Native/install/` 폴더에도 복구 스크립트가 있습니다.

`BUILD_INFO.json`에는 빌드 버전, 커밋, 소스와 DLL 해시가 들어 있습니다.
이 정보와 오프라인 검사는 배포 파일의 출처를 확인하며 실제 장비 시험을 대신하지 않습니다.
