# RE7 OTS Explore v0.3.0 design

Historical release scope: the user approved an integrated playable prototype after asking to reduce repeated diagnostic-only Steam Deck tests. This superseded the earlier observation-only next step. The original archive delivery did not modify the user's device. On 2026-10-13, the user designated like-shock/re7-ots as the code repository and authorized managing the source there; see the root README for the current workflow.

Goal: a main-game exploration camera that can be switched with F6, adjusted in REFramework UI, and tried in ordinary play while diagnostics record automatically. Native monitoring remains read-only; Lua now deliberately writes the current camera world position through the documented Transform setter. This is not a read-only observer release.

## Architecture and limits

- New RE7_OTS_Explore.dll reuses observer.c and the exact executable SHA/PE gate. It starts one worker automatically, samples at 20 Hz, and atomically replaces RE7_OTS_Explore/status.json. No engine calls, game writes or inline hooks in the DLL. Transient publication failure retries with 250 ms backoff; successful publication uses 50 ms. Worker lifetime bounded to 12 hours; DLL pinned until process exit. Old scanner/observer sources remain unchanged.
- Lua is built from small source modules into one autorun/re7_ots_explore.lua. It polls status at at most 20 Hz, requires increasing sequence/tick for freshness, and expires data after 0.35 seconds. A malformed status immediately blocks applying the camera. Supported version/schema and every consumed value are validated.
- Default OFF every script load. F6 edge toggles requested mode only when native foreground is current and REFramework UI is closed; UI checkbox is an alternative. Distance (0.2..2.0, default 0.9), shoulder (-0.6..0.6, default 0.25), height (-0.3..0.6, default 0.15) persist, enable state never persists. Settings have version and finite bounds.
- Native player/aim/inventory/interact must all be readable, with aim=0, inventory=0 and both interaction interpretations zero. Require same generations across at least 0.5 seconds of advancing native snapshots. Focus loss, stale data, invalidity, generation change, aim/inventory/interaction reset readiness. Camera/transform replacement also resets readiness.
- Apply only in pre LockScene, after pre UpdateBehavior has run in the current update cycle. Restore owned camera displacement in pre UpdateBehavior (and before any repeated apply), then obtain the engine's unmodified position anew. Camera -> GameObject -> Transform is reacquired on each access. Keep only numeric identities and coordinate copies between callbacks.
- Restoration is compare-and-restore: only same current camera/transform and current position within 0.001 of the previously applied target may be restored to the captured base. A position already at the captured base is accepted as restored. Unexpected position changes preserve the external position and latch OFF to prevent residual-offset accumulation. Immediate finite failed-setter readback on the same current camera may update the rollback comparison before cleanup. Do not overwrite another camera or an unexpected replacement. Restore errors latch OFF; setters are checked by reading back. Script reset attempts bounded cleanup.
- Offset is quaternion-rotated local right (+X) / backward (+Z), plus world Y height; camera rotation/FOV unchanged. Smooth entry over 0.15 s, immediate suspension. Broad guard: original camera within 3 units of observed player and no player jump over 5 units in adjacent accepted snapshots. Guard failure resets readiness. These are heuristics, not validated cutscene detection.
- Automatic combined JSONL journal: native values + camera before/target/after + decision and restore outcome; max 5 Hz, immediate state changes subject to same bounded rate. Two rotating fixed-name files, each at most 2 MiB, lines at most 4096 bytes. Logs never control camera lifetime. Logging failure is visible but does not strand an applied camera.

## Explicit prototype boundary

This release tests camera following and fallback behavior. No wall raycast/DOF collision, model culling patches or new head assets, FOV patch, third-person ballistics, DLC, Fullbright or exact original CT behavior. It does not claim all scripted scenes detected; users can switch OFF with F6. Aim fallback has native sampling/poll latency. A missing or headless body and wall clipping remain possible and must be stated in release instructions. Do not market this as a finished full-body third-person mod.

Test nonaccumulation over hundreds of frames, movement/rotation axes, immediate fallback, reload-generation recovery, malformed/stale/replayed status, replacement, mutation by another writer, setter and restore failure, settings corruption, callback registration/missing execution, focus/key edge, journal caps and failed I/O. Native synthetic host exercises production wrapper identity gating, initial automatic startup, limits and status publication failures. Existing 28 tests/core30/observer12 remain green. PE imports/exports and deterministic build verified. One independent code review before delivery; no Steam Deck claim from mocks.
