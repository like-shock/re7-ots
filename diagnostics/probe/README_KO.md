# RE7 OTS Native Hook Probe 0.1.0 — 장비 확인용

원본 CT 네이티브 이식에 필요한 실제 훅 대상·호출 순서를 확인하는 빌드입니다.
**3인칭 플레이 빌드가 아닙니다. 실행 중 화면은 게임의 원래 1인칭입니다.**
얼굴 숨김·모델 표시·카메라 이동·발사 좌표 변경을 하지 않습니다.
게임 실행 중 5개 명령 위치를 계측용으로 후킹하고, 원래 명령을 그대로 실행합니다.
게임 파일이나 세이브는 수정하지 않습니다.

## 설치 (Steam Deck 데스크톱 모드)

1. 게임을 완전히 종료합니다. REFramework가 이미 설치된 환경을 사용합니다.
2. 이 ZIP을 별도 폴더에 압축 해제합니다. 기존 게임 폴더에 바로 덮어쓰지 마세요.
3. 압축을 푼 폴더에서 터미널을 열고 실행합니다. 경로는 `re7.exe`가 있는 폴더입니다.

   ```bash
   bash install.sh "/게임이 설치된 폴더"
   ```

설치 스크립트는 기존 RE7 OTS Explore DLL/Lua와 Observer/Diagnostics DLL을 백업합니다.
다른 모드와 모델 파일은 이동하지 않습니다. 파일 검증에 실패하면 설치하지 않습니다.
Cheat Engine 원본 CT나 다른 카메라 모드는 함께 켜지 마세요.
F6 키 매핑은 기존 스팀덱 설정을 그대로 사용할 수 있습니다. F7은 이 빌드에서 쓰지 않습니다.

## 한 번의 확인 절차

1. 게임을 시작하고 세이브를 로드합니다. 초기 실행 파일 검사가 끝날 때까지 잠시 기다립니다.
   REFramework 로그에 `[RE7_NATIVE_PROBE] Ready`가 표시됩니다.
2. **F6을 한 번 눌러 기록을 시작합니다.** 여기서 3인칭으로 바뀌지 않는 것이 정상입니다.
3. 최대 90초 동안 가능한 동작을 한 번씩 합니다: 가만히 서 있기 → 걷기/계단 →
   벽 가까이 접근 → 물체 조사/문서 보기 → 인벤토리 열고 닫기.
   총이 있으면 조준·발사도 포함하고, 없으면 생략합니다.
4. F6을 다시 누르면 일찍 종료합니다. 90초가 지나면 자동 종료합니다.
   다른 창으로 이동한 동안은 훅 기록을 잠시 멈춥니다. 제한 시간은 계속 흐릅니다.
5. 게임을 종료하고 아래 파일을 보내주세요.

   ```text
   게임폴더/reframework/data/RE7_OTS_NativeProbe/probe_*.jsonl
   ```

실행/기록 시작이 안 되거나 종료됐다면 생성된 JSONL과 `reframework.log`를 함께 보내주세요.
계측 불가 사유도 로그에 남깁니다. 파일은 실행 1회당 최대 8 MiB입니다.
한 게임 실행에서 한 번만 기록할 수 있으며, 다시 기록하려면 게임을 재시작합니다.

## 원래 Explore로 복구

게임 종료 후 압축을 푼 폴더에서 실행합니다.

```bash
bash uninstall.sh "/게임이 설치된 폴더"
```

백업한 기존 파일이 복원되고 이 Probe DLL이 제거됩니다. 수집한 로그는 유지됩니다.
설치 이후 파일이 바뀌었거나 복원 위치에 다른 파일이 있으면 덮어쓰지 않고 중단합니다.
설치 출력에 표시되는 백업 폴더에도 `uninstall.sh`가 보관됩니다.

## 이번 장비 확인이 필요한 이유

이전 진단은 원본과 같은 명령 바이트가 있다는 것까지 확인했습니다. 이번에는 그 명령이
실행될 때의 카메라/발사/조사 대상 주소와 순서가 원본의 연결 가정에 맞는지 확인합니다.
코드 위치가 맞는다는 이유만으로 모든 객체에 카메라 좌표를 쓰지는 않습니다.

계측기는 기본 카메라 위치 수집, 카메라 쓰기, 발사 원점 쓰기, 조사 대상 좌표 쓰기,
DOF 거리 읽기 지점을 사용합니다. 로그는 일부 이벤트를 표본 수집하며 누락·버퍼 초과
수를 별도로 기록합니다. `seq`가 훅 간 순서이며 파일 줄 순서는 아닙니다.
주소 재사용 가능성이 있으므로 주소 겹침은 객체 정체성의 최종 판정이 아닙니다.
`asynchronous_*` 값은 작업 스레드가 나중에 읽은 참고 값으로, 같은 순간의 값이 아닙니다.

F6 종료 후에는 기록만 멈추고 통과용 훅과 trampoline은 게임 종료까지 유지합니다.
실행 중인 스레드가 참조할 코드를 해제하지 않기 위한 수명 정책입니다.
DLL은 해당 게임 프로세스에 고정되므로 실행 중 삭제·재로드하지 말고 게임 종료 후 복구하세요.

오프라인 검사는 명령 재배치, 레지스터/플래그/FP 상태 보존, 설치 실패 경로,
버퍼 제한과 파일 복구를 다룹니다. 실제 게임 객체·Proton 훅 설치·성능은 이 장비
확인에서 검증할 항목이며, 3인칭 이식 완료나 기존 문제 해결을 의미하지 않습니다.
